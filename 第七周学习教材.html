0.3 本周主线问题

两帧点云怎么"对齐"？ —— ① 找对应（这个点到另一个点云的哪个面/点）；② 算变换（让对应点靠得最近）；③ 迭代（重复到不再变化）。ICP/NDT 都是这个骨架，区别在"怎么找对应、怎么算距离"。

第 1 章 点云配准：把两帧拼起来

1.0 配准问题长什么样

1.0.1 场景

第一帧点云（机器狗在 A 处看到的墙）       第二帧点云（机器狗在 B 处看到的同一面墙）
        ●●●●●                                   ●●●●●
   ●●        ●●  ← 墙的轮廓                  ●●      ●●
 ●●            ●●                          ●●          ●●

两帧内容一样（同一面墙），但位置错开了（因为机器狗动了）。配准 = 求一个变换（旋转 R + 平移 t），让第二帧点云"移"回去和第一帧重合。

1.0.2 数学表达

找 R, t 使：Σ ‖ R·p_i + t − q_i ‖² 最小
             ↑                     ↑
         第二帧的点             第一帧对应的点

这就是最小二乘（第 4 周学的！）。难点："谁和谁对应"一开始不知道——鸡生蛋问题：不知道变换就不知道对应，不知道对应就不知道变换。

1.0.3 通用解法骨架（所有配准算法）

1. 猜测初始变换（初值！很重要）
2. 循环：
   a. 找对应点（最近邻）
   b. 用对应点算最优变换（SVD！第 1 周 Kabsch 学的）
   c. 应用变换，误差变小？
   d. 直到收敛

关键概念：初值。两帧差太多（初值错）→ 找错对应 → 收敛到错误结果（局部最优）。配准对初值极度敏感——这是你以后调参的核心认知。

一句话总结：配准 = 找 R、t 让两帧点云重合：找对应 → SVD 算变换 → 迭代。初值差 = 结果错。

1.1 ICP（迭代最近点）：最经典的配准

1.1.1 两种变体（记住名字和区别）

变体 怎么算"点对的距离" 特点
point-to-point（点对点） 两点距离平方 简单、快、对噪声敏感
point-to-plane（点到面） 点到"对应点所在平面"的距离 更准（用上法向量）、收敛快、常用

point-to-plane 的残差（第 1 周学过点到面距离！）：

残差 = (R·p + t − q) · n          （n = q 点的法向量）

1.1.2 ICP 的问题

  1. 初值敏感：初值差 → 错误收敛（局部最小）。
  2. 需要对应：最近邻假设"最近的就是对的"——被噪声/动态物体骗。
  3. 只适合小变形：两帧差太大基本没救。

1.1.3 收敛问题（覆盖资料任务）

  • 收敛到局部最小（不是全局）：表现为"看起来没对齐但有误差"。
  • 判断收敛：误差变化小于阈值。
  • 缓解：好初值（用 IMU/里程计给）、粗配准打底（RANSAC/NDT/特征）、降采样减少干扰点。

一句话总结：ICP = 迭代最近点：每次"找最近点→算最优变换"；点到面比点到点准；初值敏感、易局部收敛。

1.2 NDT（正态分布变换）：把点云变成"高斯场"

1.2.1 核心思想（和 ICP 根本区别）

ICP 是"点找点"；NDT 先把点云切成小格子（体素），每个格子用"均值 + 协方差"描述（一个高斯分布），然后把新帧的点往"高斯场"里配。

体素格子（每个格子一个高斯分布）：
┌─────┬─────┬─────┐
│ N(μ₁)│ N(μ₂)│ ... │   ← 描述"这里的点在什么范围"
├─────┼─────┼─────┤
│ ... │ N(μᵢ)│ ... │
└─────┴─────┴─────┘

1.2.2 优点（为什么工业界爱用）

特性 ICP NDT
初值敏感 高 较低（格子平均化更鲁棒）
速度 快 快（预先建场）
精度 高 中（格子分辨率限制）
使用场景 精细对齐 粗配准/大场景

1.2.3 关键参数：格子尺寸（体素大小）

  • 太小：场太碎，噪声大。
  • 太大：细节丢失，精度下降。
  • 经验：按点云密度选（雷达场景常见 1~3 米起步），周六实验你会亲手试不同体素。

一句话总结：NDT = 把点云"糊"成高斯场再配准；比 ICP 抗初值差，但精度受格子大小限制。

1.3 点云预处理与畸变补偿（覆盖资料任务）

1.3.1 预处理三板斧

操作 干什么 为什么
降采样 减少点数（体素滤波） 快、均匀密度
去噪 去掉孤立点/离群点 噪声会带偏配准
去地面 去掉地面点 地面点太多会"压住"结构信息

1.3.2 畸变补偿：运动中的点云扭曲（本周重点之一）

问题回顾（第 2 周学过）：一帧点云不是同一时刻采的，机器狗在扫这帧时一直在动 → 每个点带着不同的位姿 → 点云整体"拧"了（重影/扭曲）。

畸变补偿 = 把每个点"转回"到某一参考时刻的位姿下：

每个点 p_i 的采集时刻 t_i
→ 用 IMU/里程计插值出 t_i 时刻的位姿 T(t_i)
→ 把点变换到参考帧：p_i' = T(t_ref)⁻¹ × T(t_i) × p_i
→ 点云变"直"了

FAST-LIO2 的特别之处：它不显式去畸变，而是在迭代更新时用每个点自己的时间戳实时计算该时刻的位姿（把运动模型融进残差）——效果等同且更优雅。第 4 周你读的"迭代更新段"里就有它。

1.3.3 读 FAST-LIO2 畸变相关代码（周三 20 分钟）

在 LaserMapping.cpp 或 IMU_Processing.hpp 里找 point_ 相关结构（每点带时间戳），或 preprocess 里对 timestamp 的处理，标注："点的时间戳在这里被保留，供更新段使用"。

一句话总结：预处理 = 降采样+去噪+去地面；畸变补偿 = 把每个点按自己的采集时刻转回参考时刻，把"拧"的点云拉直。

1.4 FAST-LIO2 论文精读（周四，本周重头戏）

1.4.1 论文是什么

《FAST-LIO2: Fast Direct LiDAR-Inertial Odometry》（arXiv:2107.06829）。核心贡献两个：

1.4.2 贡献 1：直接配准 + iEKF（迭代误差状态卡尔曼）

  • 直接配准：不提取特征点（不挑"角点/面点"），用全部原始点直接做点到面配准。为什么可以？因为快 + ikd-Tree 快，全点更鲁棒。
  • iEKF：误差状态卡尔曼（第 6 周）+ 迭代（像 Gauss-Newton 那样反复更新，比一次 EKF 更准）。

iEKF 的迭代结构（对照第 4 周 GN）：

for iter in 1..N:
    1. 用当前状态把点云转到地图系
    2. 找每个点的最近面（ikd-Tree）
    3. 算残差（点到面距离）+ 雅可比
    4. 解增量方程，更新状态（流形上更新：旋转用 exp）
    5. 检查收敛

1.4.3 贡献 2：ikd-Tree（增量 KD-Tree）

地图要存几十万~几百万个点，还要快速"找最近点"。普通 KD-Tree 建树慢、每次重建。ikd-Tree = 支持"增量"的 KD-Tree：

操作 干什么 频率
Build 建树 初始化一次
Insert 插新点（新观测） 每帧
Delete 删旧点（机器狗走了，旧区域没用） 定期
Nearest Search 找最近邻（配准用） 每个激光点！
再平衡 树歪了自动重构 按策略

为什么重要：配准里"每个点找最近面"是性能瓶颈——ikd-Tree 让它在动态地图上保持快速。

1.4.4 读论文的方法（别从头到尾硬读）

1. 读摘要 + 图 1（系统框图）→ 20 分钟

1.5 LIO-SAM：另一种 LIO 架构（对比学习，周五）

1.5.1 LIO-SAM 是什么

LIO-SAM = 另一种开源激光惯性里程计（Tixiao Shan 等）。和 FAST-LIO2 最大区别：用因子图（优化）而不是滤波。

1.5.2 滤波式 vs 因子图式（核心对比）

FAST-LIO2（滤波式） LIO-SAM（因子图式）
状态估计 iEKF（预测+更新） 因子图优化（GN/LM 求解）
特征 全点直接配准 提取特征（角点+面点）
历史帧 不保留（状态只此一份） 保留（位姿图节点）
回环 无（FAST-LIO2 靠后续加） 内置回环检测
精度/效率 快、计算量小 更灵活、可回环，重一些

一句话：滤波式 = 轻装上阵边走边估；因子图式 = 记账本，回头能改（回环）。

1.5.3 为什么 LIO 都在给 FAST-LIO2 打底

四足机器狗工作里：FAST-LIO2 建图（快、稳）→ 建完图后导航用。回环修正由后续工具做（第 12 周 ScanContext 就是这个）。

1.5.4 画对比图（周五交付物）

画一页"FAST-LIO2 vs LIO-SAM"架构对比图（两栏对照：数据流 + 模块名），每栏标出：IMU 处理、特征/全点、状态估计、地图、回环。

一句话总结：滤波式（FAST-LIO2）= 边走边估、快；因子图式（LIO-SAM）= 记账可回环、重。架构选型看任务。

#include <pcl/io/pcd_io.h>
#include <pcl/point_types.h>
#include <pcl/registration/icp.h>

icp.setInputTarget(tgt);
icp.setMaxCorrespondenceDistance(1.0);         // 对应点最大距离
icp.setMaximumIterations(50);

pcl::PointCloud<pcl::PointXYZ> aligned;
icp.align(aligned);                            // 跑！
std::cout << "是否收敛: " << icp.hasConverged() << "\n";
std::cout << "分数: " << icp.getFitnessScore() << "\n";   // 误差
Eigen::Matrix4f T = icp.getFinalTransformation();        // 求出的变换

source = o3d.io.read_point_cloud("source.pcd")

# 1. 体素降采样（预处理）

# 2. RANSAC 全局配准（给 ICP 一个好初值）

threshold = 0.05
reg_p2p = o3d.pipelines.registration.registration_icp(
    source, target, threshold, np.identity(4),
    o3d.pipelines.registration.TransformationEstimationPointToPoint())
print(reg_p2p.fitness, reg_p2p.inlier_rmse)   # 拟合率 / 误差

附录：术语表（第 7 周新增）

术语 大白话解释
配准 把两帧点云对齐（求 R、t）
对应点 两帧里"同一个物理点"的一对点
ICP 迭代最近点：最近邻 + 变换 + 迭代
point-to-point 点到点距离的 ICP
point-to-plane 点到面距离的 ICP（更准）
法向量 平面"朝向"的方向
NDT 把点云糊成高斯场再配准
体素 三维网格的格子
降采样 减少点数（体素滤波）
去地面 去掉地面点
畸变补偿 把每个点按采集时刻转回参考时刻
局部最优 收敛到"看起来行但其实没对齐"
iEKF 迭代误差状态卡尔曼滤波
ikd-Tree 支持增量增删的 KD-Tree
惰性删除 先标记删除，攒多了再重建
最近邻搜索 找"最近的点"
因子图 把变量和约束画成图，整体优化
LIO-SAM 因子图式的激光惯性里程计
RANSAC 随机抽样一致性：鲁棒找模型（如平面）
欧式聚类 按距离把点分组
