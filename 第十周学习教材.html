0.3 本周主线问题

机器狗能走的路径，和"一个点"能走的路径有什么区别？ —— 宽度（要留身子）、转弯（不能直角拐）、坡度/台阶（脚能爬但要有约束）。规划器要想"狗的形态"。

第 1 章 全局规划器：让路径"像机器人能走的样子"

1.0 Hybrid A：A 遇上运动学

1.0.1 问题：A* 的路径狗走不了

A*（第 9 周）搜出的是"格子路径"：

A* 路径（直角转折，狗没法这样走）：
S ─→ ┐
     ├─→ G     ← 直角拐弯需要"原地转"或大圆角

狗的问题：它有运动学约束（最小转弯半径、不能横着走）。路径转折太急 = 局部规划器追不上 = 走走停停 = 卡死。

1.0.2 Hybrid A* 的答案

Hybrid A = A + 运动学模型：搜索的每一步，不是"移到相邻格子"，而是"按车辆/狗的运动学模型向前开一小段"：

搜索节点 = (x, y, yaw)    ← 多了朝向！
扩展 = 直行 / 左转固定角 / 右转固定角（用运动学模型算）
节点落地的格子 = 离散化后的 (x,y)

结果：搜出来的路径天然满足"狗能开出来"（平滑的弧线，不是直角）。

1.0.3 代价（为什么不是处处用它）

特性 A*（NavFn） Hybrid A*
状态 2D (x,y) 3D (x,y,yaw)
搜索空间 大格子 3D 网格（大）
路径质量 格子路径（有折角） 运动学可行（弧线）
速度 快 慢（状态多）
适用 简单环境/低配硬件 复杂环境/要求平滑

一句话总结：Hybrid A = A 的每个扩展步骤按运动学模型来（多了朝向 yaw），路径天然"车能开"；比 A* 慢但路径质量高。

1.1 Lattice planner：提前算好"动作库"

1.1.1 思想

Lattice = 离线生成一堆"标准动作"（格子模板），在线搜索时直接套用：

动作库（离线生成，预计算）：
 → 直行 1m / 直行 2m
 → 左转 30° 走 1m / 右转 30° 走 1m
 → 左转 60° 走 2m ...
（每个动作都是一段符合运动学的弧线）

在线搜索：状态空间 (x,y,yaw)，扩展 = 从动作库选动作

1.1.2 vs Hybrid A*

Hybrid A* Lattice
动作 在线算（每步积分运动学） 离线库（查表）
灵活性 高（任意转向角） 中（受动作库粒度限制）
速度 慢 较快
效果 路径更细 动作平滑但可能略绕

工程选型：Smac Planner 里两者都有插件（hybrid_a_star 和 lattice），配置切换。

1.2 路径平滑（smoother）：把折角"捋直"

1.2.1 问题

规划器输出的路径可能还有小折角、抖动。smoother（平滑器）在规划器和控制器之间加一层，把路径捋顺：

平滑前：●●●●●●      平滑后：●●●
              ●●●●●●            ●●●●●●

原理（gradient-based smoother）：一个优化问题——最小化"路径弯曲程度"，同时约束"别太偏离原路径、别撞障碍"：

代价 = 平滑项（曲率小）+ 距离项（别偏离太远）+ 障碍项（别撞）
用梯度下降/最小二乘迭代求解（第 4 周学的优化！）

1.2.2 和机器狗的关系

平滑路径 = 少急停、少晃动。四足狗对"急转弯"尤其敏感（会侧滑、需要重新迈步）——smoother 让 cmd_vel 更顺，第 11 周还要在控制器端再处理一次。

一句话总结：smoother = 把路径的折角捋直：优化"弯曲+偏离+碰撞"三个代价；路径顺了狗走着才稳。

1.3 四足全局约束：狗不是车（周四，重点）

1.3.1 四个方面

① footprint（脚印/外形）

车：矩形（长×宽）
狗：也要声明外形（如 1.1m × 0.5m 或圆形近似）
→ costmap 膨胀用 footprint 算（第 9 周 footprint 参数实验）
→ 窄通道能不能过 = 通道宽 vs footprint 宽

② 最小转弯

狗可以原地转（半径≈0）→ 但"边转边走"有曲率限制
→ Hybrid A* 里 min_turning_radius 参数
→ 原地转 vs 弧线转：都要在规划里考虑

③ 原地转向开关

有的场景要求"先原地转好，再直走"（更稳）vs "边转边走"（更快）
→ 规划器/控制器模式切换
→ 四足常见：旋转和前进分开执行（避免步态混乱）

④ 坡度/台阶（四足特有！）

轮式车：坡度 > 阈值 = 不可通行
四足狗：能爬台阶（但有限制：台阶高度 < 腿长，坡度 < 极限）
→ 2D costmap 看不出来 → 需要地形信息（1.4 节）

1.3.2 通过性检查清单（周四输出，本周交付物）

四足路径通过性检查清单（2026-xx-xx）
□ 1. 宽度：路径最小宽度 ≥ footprint 宽 + 2×安全边距？
□ 2. 曲率：路径最大曲率 ≤ 狗的最小转弯能力（含速度相关）？
□ 3. 原地转：需要原地转的场景是否明确（转好再走）？
□ 4. 坡度：路径最大坡度 ≤ 平台极限？
□ 5. 台阶：台阶高度 ≤ 平台可爬高度？
□ 6. 悬空：路径下方/上方障碍（2D 看不到的）是否已考虑？
□ 7. 地形：地面材质（草地/沙地）是否影响打滑/通过？

一句话总结：四足全局约束 = 外形宽度 + 转弯能力 + 原地转策略 + 坡度台阶；通过性清单把这四条落成可检查项。

3.2 任务 2：复现"路径突变"（60 分钟）

现象：导航中路径突然大改（跳一条线）。

排查（五步法）： 1. 复现：放一个动态障碍（行人/移动障碍物）在路径上。 2. 观察：全局路径什么时候跳？跳得多大？ 3. 假设：重规划频率？代价突变？ 4. 验证：调 max_planning_time、代价图更新频率等参数。 5. 记录：哪个参数让"突变"变"平滑过渡"？

输出：现象截图 + 参数→行为结论。

3.3 任务 3：复现"绕远路/走回头路"（60 分钟）

现象：路径明明可以近路直走，规划器却绕远/走回头路。

排查： 1. 复现：制造"近路代价偏高"的地图（把近路 inflate 大一点）。 2. 假设：启发式不准？costmap 代价异常？footprint 太大？ 3. 验证：逐参数对比（cost 权重、footprint、膨胀参数）。 4. 记录根因 + 修复参数。

3.4 任务 4：四足通过性实验（60 分钟）

在仿真里做（有地形/障碍场景最佳）： 1. 窄通道：宽度 = footprint × 1.1 / 1.5 / 2.0 → 记录能通过的最小宽度。 2. 台阶/斜坡（如仿真支持）：对比有/无地形代价时的路径。 3. 记录"狗"与"车"行为差异：狗会不会选择爬坡路线？
