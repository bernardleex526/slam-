部署①：用 Docker 准备 ROS 1 Noetic 环境

能构建课程提供的 Docker 镜像、进入容器、确认 ROS 1 版本，并说清镜像、容器、挂载三者的关系。

先修：23 · ROS 与 TF：数据流必须有时间和坐标

预计用时：1–2 小时（大部分时间在下载）。一次学不完就分开，第二天先闭卷重做上一段。

本课新词（2 个）：镜像 image / 容器 container、挂载 mount。随时可查 术语页。

先打个比方

镜像像一张装好系统的“光盘”，容器是用这张光盘装出来、正在运行的电脑，挂载是在这台电脑和你的真实电脑之间开了一个共享文件夹。电脑装坏了可以重装，共享文件夹里的东西还在。

比喻只帮你建立直觉；下面用数字、公式和代码把它说准确。

比方→具体问题→手算→代码→解释

一步步讲清楚

这一课开始用你最擅长的方式学：先把真实系统跑起来，再回头读懂它。我们复现的是 FAST-LIO2 官方仓库，它的 main 分支是 ROS 1 工程（catkin、roslaunch、rosbag）。上游另有独立的 ROS2 分支，命令和构建方式不同，本课不混用。

为什么用 Docker，为什么是 Noetic

ROS 1 最后一个版本 Noetic 只支持 Ubuntu 20.04。你的电脑如果是 Ubuntu 22.04/24.04 或 Windows，无法直接 apt 安装它。Docker 容器里装一个 Ubuntu 20.04 + Noetic，不会弄乱你的系统，装坏了删掉重来即可。注意：Noetic 已于 2025 年 5 月停止官方维护，用它复现论文、学习完全可以，新项目不应基于它。

第一步：装好 Docker 并自检

Ubuntu：按 Docker 官方文档“Install Docker Engine on Ubuntu”安装。Windows：安装 WSL2 和 Docker Desktop，在 WSL2 的 Ubuntu 终端里操作。然后运行：

docker run hello-world

检查点：看到 Hello from Docker!。若提示 permission denied ... docker.sock，执行 sudo usermod -aG docker $USER，注销重新登录后再试。

国内网络提示：Docker Hub、GitHub、Google Drive 都可能很慢或无法访问。需要配置你所在网络可用的镜像加速或代理。可以让 AI 帮你写 /etc/docker/daemon.json，但要问清每一行的作用，并且只用你信任的来源。

第二步：构建课程镜像

cd 课程仓库目录
docker build -t slam-noetic labs/deploy

-t slam-noetic 给镜像起名，最后的 labs/deploy 是 Dockerfile 所在文件夹。先打开 labs/deploy/Dockerfile 读一遍注释：它基于官方 osrf/ros:noetic-desktop-full，安装 Eigen、PCL，并编译 Livox-SDK。检查点：最后出现 Successfully tagged slam-noetic:latest 或 naming to docker.io/library/slam-noetic。

第三步：创建并进入容器

bash labs/deploy/run.sh

脚本会在宿主机建立 ~/slam_ws，挂载到容器的 /root/slam_ws；课程仓库以只读方式挂载到 /root/course。以后再运行同一条命令，会进入同一个容器，编译结果都还在。提示符变成 root@...:/root/slam_ws#，说明你已经在容器里了。

现象原因处理

照着做：在容器里确认环境

终端命令：在对应环境（本课为 Docker 容器内的 ROS 1 Noetic）逐条执行，每条都对照检查点。

# 在容器里逐条运行，并对照右侧期望
rosversion -d                         # 期望：noetic
echo $ROS_DISTRO                      # 期望：noetic
ls /root/slam_ws                      # 期望：catkin_ws  data  ws_livox
ls /usr/local/lib | grep -i livox     # 期望：liblivox_sdk_static.a
roscore                               # 期望：started core service [/rosout]；Ctrl+C 退出

rosversion -d 输出 noetic，说明加载的是 ROS 1；如果什么都不输出，是当前终端没有 source /opt/ros/noetic/setup.bash（课程镜像已写进 .bashrc，新开的 bash 会自动加载）。roscore 是 ROS 1 的“总机”，所有节点要先找它登记；ROS 2 没有 roscore，这是区分两代 ROS 的最快办法。

先独立作答，再打开提示

在宿主机的 ~/slam_ws/data 里放一个文件 a.bag，它在容器里的完整路径是什么？在容器里删除它，宿主机上还在吗？

提示：只给下一步

run.sh 里写的是 -v "$WS":/root/slam_ws，冒号左边是宿主机，右边是容器。

核对解答与常见错因

容器里是 /root/slam_ws/data/a.bag。挂载是同一份文件的两个入口，在容器里删除，宿主机上也没了。所以重要的录包要另外备份；反过来，删掉容器不会删除挂载目录里的文件。

若还无法解释，回到先修：23 · ROS 与 TF：数据流必须有时间和坐标。闭上答案，换一组数字重算。

改变条件的迁移练习与解析

你想彻底重装环境：执行 docker rm -f slam-noetic 后再运行 run.sh。哪些东西会丢，哪些不会？容器里在挂载目录以外装的软件会丢；~/slam_ws 里的源码、编译结果和录包都在。镜像 slam-noetic 也还在，不需要重新 build。
