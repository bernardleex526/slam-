位姿与变换链：先看清是“谁到谁”

能读懂 T_AB 的方向，用齐次矩阵把多个变换串起来，并会求逆变换；认识 SO(3)、SE(3) 这些名字。

先修：13 · 三维旋转：从平面转动推广到空间

预计用时：2–3 次 × 40 分钟。一次学不完就分开，第二天先闭卷重做上一段。

本课新词（4 个）：位姿 pose、SO(3) / SE(3)、李代数 Lie algebra、齐次变换 homogeneous transform。随时可查 术语页。

先打个比方

变换链像翻译接力：雷达说“雷达语”，先翻译成“机身语”，再翻译成“地图语”。T_BL 是“雷达语→机身语”的词典，T_WB 是“机身语→地图语”的词典。词典拿反了，翻译出来就是胡话。

比喻只帮你建立直觉；下面用数字、公式和代码把它说准确。

比方→具体问题→手算→代码→解释

从实际问题走到公式

位姿 = 位置 + 朝向。机器人上每个部件（雷达、IMU、相机）都有自己的坐标系，一个激光点必须经过一串变换才能画到地图上。

第一步：约定方向

pᴬ = R_AB pᴮ + t_AB

本教材固定：T_AB 把 B 坐标系里的坐标变到 A。t_AB 是 B 的原点在 A 中的位置，R_AB 是 B 的朝向相对 A 的旋转。读下标时从右往左读：“从 B 到 A”。不同项目的约定可能相反，读别人代码前先找它的定义。

第二步：齐次矩阵，把旋转和平移合成一次乘法

给点补一个 1，写成 [x, y, 1]（三维是 [x, y, z, 1]），旋转和平移就能放进同一个矩阵：二维是 3×3，三维是 4×4。

T = [[R, t], [0, 1]]

好处是串联变换只需要矩阵相乘：T_WL = T_WB · T_BL。右边先作用：点先从雷达 L 到机身 B，再从机身到地图 W。中间的 B 像接力棒一样“相邻抵消”。如果写成 T_BL · T_WB，维度能乘，但含义不成立。

第三步：逆变换

从地图回到机身：T_BW = T_WB⁻¹。旋转部分是 Rᵀ（第 07 课：旋转矩阵的转置就是逆），平移部分是 −Rᵀt。它不是把所有元素加个负号。验证办法：正变换后再逆变换，应回到原来的点。

第四步：几个以后会遇到的名字（只需认识）

SO(3)：所有合法三维旋转矩阵的集合（RᵀR=I 且行列式为 1）。SE(3)：所有“旋转+平移”刚体变换的集合。李代数：优化旋转时不能直接给矩阵的 9 个数各加一点（会破坏约束），而是用 3 个数表示“一个小转动”，再转换成合法旋转。看到 FAST-LIO2 代码里的 Exp、Log、⊞ 时，只要知道它们在做“合法地加一个小增量”就够了，推导等你需要改这部分代码时再学。

把公式落实到每行代码

Python：可直接运行。先写下预测，再运行核对。

import math

def make_T(x, y, deg):
    c, s = math.cos(math.radians(deg)), math.sin(math.radians(deg))
    return [[c, -s, x], [s, c, y], [0, 0, 1]]

def matmul(A, B):
    return [[sum(A[i][k] * B[k][j] for k in range(3)) for j in range(3)] for i in range(3)]

def apply(T, p):
    v = [p[0], p[1], 1.0]
    return [round(sum(T[i][k] * v[k] for k in range(3)), 6) + 0.0 for i in range(2)]

T_WB = make_T(2.0, 1.0, 90)    # 机身在地图中：位置 (2,1)，朝向 90°
T_BL = make_T(0.2, 0.0, 0)     # 雷达装在机身前方 0.2 米，没有转角
T_WL = matmul(T_WB, T_BL)
print(apply(T_WL, [1.0, 0.0])) # 雷达看到正前方 1 米处的点

输出 [2.0, 2.2]。手算核对：雷达里的 (1,0) 先加上安装偏移，在机身里是 (1.2,0)；机身朝向 90°，“前方”是地图的 +y，旋转后是 (0,1.2)；再加机身位置 (2,1)，得 (2,2.2)。make_T 就是二维齐次矩阵，matmul 是矩阵乘法的三重求和。用二维是为了能手算，三维只是把 3×3 换成 4×4。

先独立作答，再打开提示

把 matmul(T_WB, T_BL) 改成 matmul(T_BL, T_WB)，输出会变成什么？为什么说它没有物理意义？

提示：只给下一步

先算新矩阵的平移部分：R_BL·t_WB + t_BL。

核对解答与常见错因

输出 [2.2, 2.0]。顺序反了以后，相当于把“机身在地图中的位置”当成雷达坐标里的量再平移，下标接不上（B 和 W 不相邻）。代码不会报错，结果却是错的。这类错误只能靠检查下标方向和手算核对发现。

若还无法解释，回到先修：13 · 三维旋转：从平面转动推广到空间。闭上答案，换一组数字重算。

改变条件的迁移练习与解析

机器人位于 (2,1)、朝向 90°，地图上有一点 (2,3)。它在机身坐标里是多少？先减平移得 (0,2)，再反向旋转 90°，得 (2,0)：在机身正前方 2 米。用代码验证：写一个 inverse 函数，或者检查 apply(T_WB, [2,0]) 是否回到 (2,3)。

一句话总结
