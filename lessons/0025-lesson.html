部署②：编译 FAST-LIO2 并回放公开录包

能亲手编译 livox_ros_driver 和 FAST_LIO，记录版本，回放官方 Avia 录包，在 rviz 里看到轨迹和地图，并保存点云。

先修：24 · 部署①：用 Docker 准备 ROS 1 Noetic 环境

预计用时：半天（含下载录包）。一次学不完就分开，第二天先闭卷重做上一段。

本课新词（4 个）：工作空间 workspace、source 环境、录包 rosbag、提交号 commit。随时可查 术语页。

先打个比方

编译像按菜谱备菜：先备好调料（livox_ros_driver 的消息类型），才能做主菜（FAST_LIO）；source 像把调料摆上灶台，没摆上去，厨师就说“找不到盐”。回放录包像放一段录像给机器人看，它会以为自己正在现场。

一步步讲清楚

本课每一步都有检查点。没通过就停下，到部署③按现象查，不要带着错误往下做。下方代码框是全部命令；正文解释每一段在做什么。

第一段：编译 livox_ros_driver

FAST_LIO 的代码里用到了 Livox 雷达的消息类型 livox_ros_driver/CustomMsg，所以即使你用别的雷达，也要先编译它。工作空间（workspace）是一个固定结构的文件夹：源码放在 src，catkin_make 编译后生成 build 和 devel。编译完必须 source devel/setup.bash，当前终端才“认识”这个包。

检查点 1：catkin_make 最后显示 [100%] Built target ...，没有红色 error。

第二段：编译 FAST_LIO，并记录版本

在已经 source 了 ws_livox 的同一个终端里编译 FAST_LIO。git submodule update --init 会下载它依赖的 ikd-Tree 等子模块，漏掉这一步会出现找不到头文件的错误。git rev-parse HEAD 打印当前提交号，把它记下来：以后别人复现、你读源码对照行号，都以这个提交为准。

检查点 2：rospack find fast_lio 输出一个路径，而不是 Error: package 'fast_lio' not found。

第三段：准备录包，先体检再运行

从 FAST_LIO 官方 README 第 4.1 节（Livox Avia Rosbag）的链接下载任意一个录包，放到宿主机 ~/slam_ws/data/。先 rosbag info 看看里面有什么，再用课程的体检脚本对照 FAST_LIO 的配置文件 config/avia.yaml。

检查点 3：录包里有 /livox/lidar（类型 livox_ros_driver/CustomMsg）和 /livox/imu（sensor_msgs/Imu），体检脚本显示“通过”。

第四段：运行，两个终端

终端 A 启动 FAST_LIO（会自动启动 roscore 和 rviz）；等它显示等待数据后，终端 B 回放录包。检查点 4：rviz 中出现彩色点云并不断增长，坐标系显示 camera_init 与 body。终端 C（可选）运行 rostopic hz /Odometry，应有约 10 Hz 的输出（与雷达帧率一致）。

avia.yaml 默认 path_en: false，所以 /path 话题没有数据，这不是故障；想看轨迹线，可把它改成 true 后重新启动（修改 yaml 不需要重新编译）。

第五段：保存结果，留下证据

avia.yaml 默认 pcd_save_en: true。录包放完后在终端 A 按 Ctrl+C，FAST_LIO 会把整张地图存到 FAST_LIO/PCD/scans.pcd，可用 pcl_viewer 查看。检查点 5：文件存在且能打开。

最后在学习记录里写下：FAST_LIO 提交号、录包文件名、运行命令、一张 rviz 截图、遇到的问题和解决方法。这就是第 33 课“关卡 B”要求的复现证据的第一份草稿。

照着做：完整命令（每段做完先过检查点）

终端命令：在对应环境（本课为 Docker 容器内的 ROS 1 Noetic）逐条执行，每条都对照检查点。

# ── 第一段：livox_ros_driver（容器内）
cd /root/slam_ws/ws_livox/src
git clone https://github.com/Livox-SDK/livox_ros_driver.git
cd /root/slam_ws/ws_livox && catkin_make
source devel/setup.bash

# ── 第二段：FAST_LIO（同一个终端）
cd /root/slam_ws/catkin_ws/src
git clone https://github.com/hku-mars/FAST_LIO.git
cd FAST_LIO && git submodule update --init
git rev-parse HEAD | tee -a /root/slam_ws/data/versions.txt
cd /root/slam_ws/catkin_ws && catkin_make
source devel/setup.bash
rospack find fast_lio

# ── 第三段：体检录包（把文件名换成你下载的）
cd /root/slam_ws/data
rosbag info 你的录包.bag | tee info.txt
python3 /root/course/labs/deploy/check_bag.py info.txt \
    /root/slam_ws/catkin_ws/src/FAST_LIO/config/avia.yaml

# ── 第四段：终端 A
roslaunch fast_lio mapping_avia.launch
# ── 终端 B（docker exec -it slam-noetic bash 进入，再 source 工作空间）
source /root/slam_ws/catkin_ws/devel/setup.bash
rosbag play /root/slam_ws/data/你的录包.bag

# ── 第五段：终端 A 按 Ctrl+C 之后
pcl_viewer /root/slam_ws/catkin_ws/src/FAST_LIO/PCD/scans.pcd

如果你只想先看到结果，可以运行 bash /root/course/labs/deploy/build_fastlio.sh，它自动完成第一、二段并写入版本记录。建议至少手动做一遍：自己敲过的命令出错时，你才知道是哪一步。每个新终端都要 source 工作空间；FAST_LIO 的 devel 已经叠加了 ws_livox，所以只 source 它就够了。脚本会把这一行写进 .bashrc，之后新开的终端会自动加载。

先独立作答，再打开提示

官方 README 说 Livox 雷达只支持 livox_lidar_msg.launch 录出的 CustomMsg，不支持 livox_lidar.launch 发布的 PointCloud2。结合第 16 课的去畸变，解释为什么。

提示：只给下一步

去畸变需要知道每个点是在扫描中的哪个时刻测到的。

核对解答与常见错因

CustomMsg 为每个点保存了相对时间，FAST_LIO 用它和 IMU 把每个点补偿到同一时刻；PointCloud2 版本缺少逐点时间，运动中扫描的点无法正确去畸变。表现是快速转弯时地图重影或漂移。这也是为什么部署前要先体检“话题类型”，而不只看话题名。

若还无法解释，回到先修：24 · 部署①：用 Docker 准备 ROS 1 Noetic 环境。闭上答案，换一组数字重算。

改变条件的迁移练习与解析

你换成 Velodyne 录包，运行 mapping_velodyne.launch 后终端出现 Failed to find match for field 'time'。按 README 的说明，这表示什么？下一步查什么？表示点云里没有逐点时间戳字段。先用 rostopic echo -n 1 话题 --noarr 看点云有哪些字段，再查 velodyne.yaml 里的 timestamp_unit 和驱动设置，不要先去改算法参数。
