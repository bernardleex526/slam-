C++③：Eigen 与 CMake：把矩阵搬进一个小工程

能用 Eigen 写出第 07 课的旋转，用 CMake 编译一个小工程，并能先写维度再读矩阵表达式。

先修：21 · C++②：函数、引用与 const：数据是复制还是共用；14 · 位姿与变换链：先看清是“谁到谁”

预计用时：2–3 次 × 40 分钟。一次学不完就分开，第二天先闭卷重做上一段。

本课新词（2 个）：Eigen、CMake。随时可查 术语页。

先打个比方

Eigen 像一台专业计算器，矩阵乘法一个 * 号就搞定；CMake 像装修队的施工图，告诉编译器“用哪些文件、到哪里找库、最后装出什么”。ROS 的 catkin_make 就是在 CMake 上又包了一层。

比喻只帮你建立直觉；下面用数字、公式和代码把它说准确。

一步步讲清楚

前面用 Python 手写三重循环做矩阵乘法，是为了看清每一步。真实工程用 Eigen 这个 C++ 线性代数库，FAST-LIO2 里几乎每个公式都是 Eigen 表达式。

第一步：Eigen 的几个基本类型

Eigen::Matrix2d 是 2×2 的 double 矩阵，Eigen::Vector2d 是 2 个 double 的列向量；三维对应 Matrix3d、Vector3d，4×4 齐次矩阵是 Matrix4d。R << 0, -1, 1, 0; 按行依次填数，这里的 << 是 Eigen 定义的“填充”，不是输出。R * p 就是矩阵乘向量，R.transpose() 是转置。

第二步：先写维度，再读表达式

读到 H * delta 这样的式子，先在纸上标维度：H 是 N×6、delta 是 6×1，结果就是 N×1，表示“每个观测的预测变化”。如果标出来是 6×1，多半是你把雅可比的方向看反了。Eigen 在维度不匹配时，编译期或运行时会报错，报错信息很长，找其中的 YOU_MIXED_MATRICES_OF_DIFFERENT_SIZES 之类大写提示。

第三步：用 CMake 组织工程

单文件可以直接 g++，但 Eigen 要告诉编译器头文件在哪里，文件一多就需要 CMake。一个最小的 CMakeLists.txt：

cmake_minimum_required(VERSION 3.10)
project(eigen_demo)
set(CMAKE_CXX_STANDARD 17)
find_package(Eigen3 REQUIRED)
add_executable(eigen_demo main.cpp)
target_link_libraries(eigen_demo Eigen3::Eigen)

逐行意思：要求的 CMake 版本；工程名；C++ 版本；找到 Eigen（找不到就停下报错）；用 main.cpp 生成程序 eigen_demo；让这个程序使用 Eigen。

第四步：标准的编译四连

sudo apt install cmake libeigen3-dev   # 只需一次
cd labs/cpp/eigen_demo
mkdir -p build && cd build
cmake ..
make
./eigen_demo

cmake .. 读取上一级的 CMakeLists.txt，生成编译计划；make 真正编译。把编译产物放在 build 文件夹里，删掉它就能“从头再编”。你以后在 ROS 里执行的 catkin_make，本质上就是对整个工作空间做 cmake + make。

常见报错：Could not find a package configuration file provided by "Eigen3"：没装 libeigen3-dev，或 CMake 找不到它。部署 FAST-LIO2 时遇到 provided by "livox_ros_driver"，原因属于同一类：依赖没装好，或者没有 source 依赖的工作空间。

文件：labs/cpp/eigen_demo/main.cpp（按上面四步编译）

C++：需要在 Linux 中编译后运行，命令见上文。

#include <Eigen/Dense>
#include <iostream>

int main() {
    Eigen::Matrix2d R;
    R << 0, -1,
         1,  0;                          // 绕 z 转 90°，按行填写
    Eigen::Vector2d p(1, 0), t(2, 1);
    Eigen::Vector2d world = R * p + t;   // 第 07 课的 pᵂ = R pᴮ + t
    Eigen::Vector2d back = R.transpose() * (world - t);
    std::cout << world.transpose() << "\n";
    std::cout << back.transpose() << "\n";
    return 0;
}

输出 2 2 和 1 0。第一行与第 07 课手算的 (2,2) 一致；第二行用 Rᵀ(pᵂ−t) 做逆变换，回到了原来的 (1,0)。.transpose() 只是为了横着打印，world 本身仍是 2×1 列向量。这个“正变换后再逆变换、看能不能回去”的检查，是验证坐标代码最便宜的办法。

提示：只给下一步

看相邻的两个数字是否相等。

核对解答与常见错因

3×2 乘 2×1 可以，结果 3×1；2×3 乘 2×1 不行，中间的 3 和 2 对不上，Eigen 会报错。不要因为“元素个数差不多”就以为能乘。

改变条件的迁移练习与解析
