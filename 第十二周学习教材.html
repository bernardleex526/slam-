第 1 章 回环检测与位姿图优化

1.0 问题：累积漂移

1.0.1 为什么需要回环

机器狗建图走一大圈（比如 100 米）：

理想：回到起点时，起点重合。
现实（无回环）：回到起点时，起点偏了 1 米！  ← 累积漂移（每步错一点点，攒起来）

FAST-LIO2 本身没有回环（第 7 周学过：滤波式不保留历史帧）——它靠局部配准一路推，走远了必漂。回环检测 = 认出"我回到了熟悉的地方"→ 用这个信息把地图整体拉闭合。

1.0.2 完整流程（先看全景，周二画图）

① 回环检测：当前点云 vs 历史点云 → "这地方我来过"（相似度分数）
② 几何验证：ICP 精配准当前帧与候选帧 → 得到回环约束（相对位姿）
③ 拒绝误检：验证失败的（几何对不上）→ 丢掉
④ 位姿图优化：把"回环约束"加进图里，整体优化所有位姿
⑤ 地图更新：优化后的位姿重新投影点云 → 地图闭合

一句话总结：回环 = 认出旧地 → ICP 验证 → 加入优化 → 整体修正。没有它，地图走远了必漂。

1.1 ScanContext：给"一帧点云"造指纹（周一）

1.1.1 问题

回环检测的难点：从几十万个点里，快速判断"这帧我见过吗"。逐点比较太慢（几十万×几十万）。ScanContext 的思路：把一帧点云压缩成一个"指纹"（描述子），比指纹就快了。

1.1.2 怎么造指纹（三步）

① 极坐标网格化：以雷达为圆心，把 360° 分成一圈圈扇区
   （半径分成 20 圈 × 角度分成 60 扇区 = 1200 个格子）
② 每个格子填"该区域最高点的高度"（一个数）
   → 得到一个 20×60 的矩阵 = 这帧点云的"指纹"
③ 为什么这个指纹好用：
   - 只看高度 → 对旋转鲁棒（转 90° = 指纹列循环移位）
   - 压缩了几十万点 → 一个 1200 数的矩阵（快！）

指纹长这样（示意）：

    扇区 0   扇区 1   ...   扇区 59
环0  [3.2]  [3.1]  ...  [3.0]     ← 最内圈（离雷达近）
环1  [2.5]  [2.6]  ...  [2.4]
...
环19 [0.3]  [0.2]  ...  [0.1]     ← 最外圈

1.1.3 怎么比指纹

  • Ring Key（一圈的压缩指纹）：每圈算一个哈希值（如最高点所在列）→ 先比 ring key 快速筛出候选（不用全比）。
  • 相似度：两个指纹矩阵逐格比对（考虑列循环移位，即任意朝向），分数高 = 像。

1.1.4 读官方源码（周一任务）

github.com/SignalImageCV/scancontext，核心函数：

makeScancontext(...)      # 造指纹（找极坐标网格化 + 高度填充）
makeRingkeyFromScancontext(...)  # 造圈指纹（快速筛选）
distanceBtnScanContext(...)      # 比两个指纹的相似度

记录：每个函数输入输出 + 一句"它干什么"。

一句话总结：ScanContext = 把点云压成"极坐标高度指纹"；先比 ring key 快筛，再比相似度确认；转一圈指纹只是列移位，天然抗旋转。

1.2 回环完整流程（周二）

1.2.1 候选检索

每来一帧（或隔一段）：
1. 造指纹
2. 比 ring key：和历史所有帧的 ring key 比（哈希表，O(1) 级）
3. 得到 top-k 候选（最像的几帧）
4. 检查：候选帧与当前帧时间相隔够远吗？（太近 = 不是回环，是连续帧）
5. 相似度 > 阈值 → 候选通过

1.2.2 几何验证（拒绝误检）

为什么必须验证：指纹相似 ≠ 真回环（相似环境到处都是，如长的走廊）。用 ICP（第 7 周）：

用候选帧位姿做初值，ICP 配准当前帧与候选帧
- 收敛且误差小（分数高）→ 真回环 → 约束 = ICP 求出的相对位姿
- 不收敛/误差大 → 假回环 → 丢弃

1.2.3 位姿图优化（第 1.3 节细讲）

把回环约束加进图 → 优化 → 地图闭合。

1.2.4 周二输出：流程图

画"回环检测 → 位姿图 → 优化"完整流程图（每框标输入输出）。

一句话总结：回环流程 = ring key 快筛 → 相似度确认 → 时间检查 → ICP 几何验证 → 加入位姿图优化。每一步都在拒绝假回环。

1.3 因子图与 GTSAM（周三）

1.3.1 位姿图（Pose Graph）：把轨迹画成"珠子项链"

每个位姿 = 一颗珠子（节点）
相邻位姿的相对变换 = 珠子间的线（边/约束）
回环 = 一颗"远端珠子"和当前珠子之间突然加了一根线（回环约束）

优化前：项链两端对不上（漂移）
优化后：整体调整珠子位置，让所有"线"都尽量吻合 → 两端闭合

1.3.2 因子图（Factor Graph）

因子图 = 位姿图 + 观测约束（比位姿图更一般）：

变量节点：要估计的量（位姿）
因子节点：约束/观测（相邻约束、回环约束、里程计、GPS...）

读法：变量画圆、因子画方块、因子连接它涉及的变量。优化 = 调整变量，让所有因子描述的约束都尽量满足 = 最小二乘（第 4 周！）。

1.3.3 GTSAM（因子图库）

GTSAM = 佐治亚理工的开源因子图库（SLAM 标配）：

#include <gtsam/geometry/Pose2.h>
#include <gtsam/nonlinear/NonlinearFactorGraph.h>
#include <gtsam/nonlinear/LevenbergMarquardtOptimizer.h>
#include <gtsam/slam/BetweenFactor.h>

// 1. 建图
gtsam::NonlinearFactorGraph graph;

// 2. 加约束：位姿0 到 位姿1 的相对变换（如向右 1m）
gtsam::Pose2 pose01(1.0, 0.0, 0.0);
graph.add(gtsam::BetweenFactor<gtsam::Pose2>(0, 1, pose01));

// 3. 初始猜测
gtsam::Values initials;
initials.insert(0, gtsam::Pose2(0, 0, 0));
initials.insert(1, gtsam::Pose2(0.8, 0.2, 0.1));   // 粗略猜

// 4. 优化（LM，第 4 周学的！）
gtsam::LevenbergMarquardtOptimizer optimizer(graph, initials);
gtsam::Values result = optimizer.optimize();

// 5. 看结果
std::cout << "位姿1优化后: " << result.at<gtsam::Pose2>(1) << std::endl;

和你的知识连接：BetweenFactor = 约束；LM 优化 = 第 4 周；Pose2(x, y, theta) = 位置 + 朝向（平面）。你三个月学的所有东西在这里汇合了。
