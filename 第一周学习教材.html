0.4 整个一周就回答一个问题

机器狗是怎么知道"我在哪里"的？

答案的骨架（先用大白话说，学完这本书你能说出数学细节）：

  1. 机器狗身上有激光雷达（每秒射出几十万个激光点，碰到障碍物弹回来，算出障碍物距离）和 IMU（像手机里的陀螺仪+加速度计，感受身体旋转和晃动）。
  2. 激光点能告诉我们"周围长什么样"（一面墙、一棵树）。
  3. IMU 能告诉我们"我刚刚怎么动的"（往左转了多少、往前颠了多少）。
  4. 计算机把它们合起来猜："根据 IMU 我大概在这 → 那激光应该看到这些点 → 咦，实际看到的点有点偏 → 修正一下我的位置"。
  5. 这个过程反复进行 = 一边猜自己在哪、一边把周围的点拼成地图。这就是 SLAM（同步定位与建图）。

FAST-LIO2 就是干这件事的程序（"FAST" 快，"LIO" = 激光 + 惯性里程计）。你这一周要学的数学（线性代数）就是第 4 步"怎么修正位置"用的工具，C++ 和 Eigen 是写这个工具的语言。

第 1 章 线性代数（从零开始）

1.0 预备：把初中数学捡回来（10 分钟）

1.0.1 坐标系：给世界贴门牌号

你小时候在方格纸上画过点。坐标系就是给平面上每个位置起名字的系统：

    y
    |
  3 |      ● (2, 3)      ← 这个点的"门牌号"是 (2, 3)
    |
  2 |
    |
  1 |
    |
    +----+----+----> x
        1    2    3

三维就是多一个方向：墙上的画是 (x, y)，房间里的东西还要加上"离地面多高"——(x, y, z)。
  • 读法：先横着走 x 步，再竖着走 y 步。坐标 (2, 3) = 向右 2、向上 3。
  • 激光雷达测到的每个点，就是三维坐标 (x, y, z)：x = 前后，y = 左右，z = 高低。

1.0.2 函数：一台"输入→输出"的机器

函数就是一个规则：给它一个数，它算出一个数。 比如"加 1 函数"：输入 2 → 输出 3；输入 5 → 输出 6。

写成符号：f(x) = x + 1（读作：f of x 等于 x 加 1）。x 是输入（自变量），f(x) 是输出。

为什么学函数：机器狗里全是函数——"输入当前速度，输出 0.1 秒后在哪里"，"输入两个点，输出它们的距离"。看懂函数 = 看懂程序在算什么。

1.0.3 sin 和 cos：直角三角形里的比例

画一个直角三角形，其中一个角是 θ：

        /
   斜边 /|
       / |
      /  | 对边        sin(θ) = 对边 ÷ 斜边
     /___|
    邻边                cos(θ) = 邻边 ÷ 斜边
  • sin(θ) = 对边长度 ÷ 斜边长度（念"塞因"）
  • cos(θ) = 邻边长度 ÷ 斜边长度（念"扣塞因"）

几个必须记住的常用值（θ 用度数）：

θ（度） 0° 30° 45° 90°
sin(θ) 0 0.5 0.707 1
cos(θ) 1 0.866 0.707 0

为什么学 sin/cos：旋转就是靠它们算的。一个点绕原点转 θ 度后去哪了？答案里全是 sin 和 cos（见 1.5 节）。机器狗扭头、翻身，数学上都写成 sin/cos。

一句话总结：坐标 = 门牌号；函数 = 输入输出机器；sin/cos = 直角三角形两边的比例。

1.1 向量：带方向的箭头（相当于 3B1B 第 1 集）

1.1.1 先打比方

你家在"往东走 3 公里、往北走 2 公里"的地方。这个"往东 3、往北 2"就是一个向量——它不只是个数，还带着方向和大小。

  • 点 (3, 2)：就是那个位置本身（门牌号）。
  • 向量 (3, 2)：是从原点"出发，往东 3、往北 2"这个动作（箭头）。

区别：点是位置，向量是"怎么走过去"。但在数学里它俩长得一模一样，都用 (x, y, z) 写。激光雷达的一个点，我们既把它当"位置"，也把它当"从雷达出发指向障碍物的箭头"——什么时候当哪个，看语境。

1.1.2 向量的加法：先走一段，再走一段

"先往东 3、往北 2，再往东 1、往北 4" = 总共"往东 4、往北 6"。

(3, 2) + (1, 4) = (4, 6)

规则：对应的分量分别相加（第一个加第一个，第二个加第二个）。

生活例子：位移就是向量加法。机器狗"先走 1 米再走 2 米"，位移 = 1 + 2 = 3 米（方向相同时）。

1.1.3 向量的数乘：把箭头拉长缩短

"往东 3、往北 2"走 2 遍 = "往东 6、往北 4"。

2 × (3, 2) = (6, 4)        拉长 2 倍，方向不变
-1 × (3, 2) = (-3, -2)     方向转 180°（往回走）
0.5 × (3, 2) = (1.5, 1)    缩短一半

规则：每个分量都乘以这个数。

1.1.4 小总结：向量是什么

  • 三个视角：物理（箭头）、计算（一列数字）、几何（箭头在坐标里的样子）。
  • 两个操作：加法（首尾相接）、数乘（拉长/缩短/反向）。
  • 线性代数里 90% 的运算，都是这两个操作的组合。

一句话总结：向量 = 带方向的箭头 = 一列数字；加法 = 走两步；数乘 = 拉长缩短。

1.2 线性组合、张成空间、基：用积木拼出一切（相当于 3B1B 第 2 集）

1.2.1 先打比方：调颜料

调颜料时：红色颜料 + 蓝色颜料 = 紫色。"红 3 份 + 蓝 2 份"这种配方，数学上叫"红和蓝的线性组合"。

向量也一样：把两个向量"各自缩放再相加"：

3 × (1, 0) + 2 × (0, 1) = (3, 0) + (0, 2) = (3, 2)

(3, 2) 就是向量 (1,0) 和 (0,1) 的一个线性组合（配方：3 份第一个 + 2 份第二个）。

1.2.2 张成空间（span）：用这些积木能拼出哪些位置？

"两个向量张成的空间" = 用这两个向量（任意缩放、任意组合）能到达的所有位置的集合。

  • 两个方向不一样的向量（比如 (1,0) 和 (0,1)）：能拼出整个平面上任意位置 → "张成整个平面"。
  • 两个方向一样的向量（比如 (1,1) 和 (2,2)）：只能拼出一条直线上的位置。
  • 三个不在同一平面的向量（比如 (1,0,0)、(0,1,0)、(0,0,1)）：能拼出整个三维空间。

直觉：积木种类越多、方向越不重复，你能搭出的位置越多。

1.2.3 基（basis）：最精炼的积木组

基 = 一组"刚好够用、一个不多"的向量，用它们能拼出空间里的任意位置，而且每个位置的"配方"是唯一的。

  • 标准基：(1,0,0)、(0,1,0)、(0,0,1)（三维空间的"米尺"）。
  • 坐标 (3, 2, 1) 的意思 = 配方"3 个 (1,0,0) + 2 个 (0,1,0) + 1 个 (0,0,1)"。
  • 基不唯一：(1,1) 和 (1,-1) 也能当二维的基，只是坐标值会变。

判断"是不是基"：① 能拼出整个空间（张成）；② 彼此方向不重复（线性无关）。

1.2.4 关键洞察：坐标 = 配方

"这个点的坐标是 (x, y, z)" 的真正意思是："用 x 份第一根积木 + y 份第二根积木 + z 份第三根积木，可以拼到这个点。"

1.2.5 和机器狗的关系（重要！）

机器狗身上有好多套坐标系（你可以理解为好多套"积木/尺子"）：

  • 雷达坐标系：以雷达为原点，"往前"是它的 x 轴。
  • 机体坐标系：以机器狗身体中心为原点，"狗头方向"是 x 轴。
  • 世界坐标系：以出发点为原点，固定不动。

同一个点（比如墙上的钉子），在不同坐标系里的坐标不同——因为它分别用不同的尺子量。坐标系变换 = 换一套尺子量同一个东西。 这就是后面 1.11 节要讲的"基变换"。

一句话总结：线性组合 = 调配方；张成 = 能拼出的所有位置；基 = 最精炼的积木组；坐标 = 配方。

1.3 线性变换与矩阵：把整个空间扭一下（相当于 3B1B 第 3 集）

1.3.1 先打比方：游戏里的变形

游戏里把整个画面"压扁"或"拉长"，每个像素都移动了，但直线还是直线、格子还整齐——这种"把整个空间规规矩矩地变形"就叫线性变换。

两条规则（数学定义）：

① 变换后，直线还是直线（格子保持平行、间距均匀）
② 原点（0,0）不动

反例：平移（整个画面往右挪）原点动了，所以平移不是线性变换。这就是为什么机器人位姿要写两半：旋转矩阵（线性变换）+ 平移向量（不是）。

1.3.2 矩阵 = 变形的"说明书"

关键魔法：只要知道两根积木（基向量）被扭到哪里，就能知道所有点的去向。

因为任意点 = "x 份积木1 + y 份积木2"，变形后 = "x 份变形后的积木1 + y 份变形后的积木2"。

所以变形的全部信息，就是两张照片：积木1 去哪了、积木2 去哪了。把它们并排写在一起：

变形后积木1 变形后积木2
    ↓           ↓
 |  a    b  |
 |  c    d  |     ← 这就是一个"矩阵"（数字方阵）

矩阵 = 变形说明书。矩阵的每一列 = 一个基向量被扭到了哪里。

1.3.3 矩阵 × 向量 = 按说明书变形

| 2  0 |   | 1 |       | 2 |
| 0  2 | × | 1 |  =    | 2 |

读法：基向量 (1,0) 被扭到 (2,0)（向右拉长 2 倍），(0,1) 被扭到 (0,2)（向上拉长 2 倍）。所以点 (1,1) 被扭到 (2,2)。整个平面被放大了 2 倍。

计算规则（重要，背下来）：

矩阵 × 向量 = "用向量的分量去组合矩阵的列"

| a  b |   | x |          | x × 第1列 + y × 第2列 |
| c  d | × | y |    =     |                        |

例：

| 0  -1 |   | 1 |     =  1 × | 0 |  +  0 × |-1 |   =  | 0 |
| 1   0 | × | 0 |         | 1 |       | 0  |        | 1 |

即 (1,0) → (0,1)：逆时针转 90°。所以这个矩阵就是"转 90°"的说明书。

1.3.4 和机器狗的关系

机器狗的位姿（位置+姿态）就是一个变换：把雷达测到的点，从雷达坐标系"变形"到世界坐标系。

p_world = R × p_body + t
          ─┬──   ──┬──   ─
      旋转矩阵   点坐标   平移向量
  • R（旋转矩阵）：负责"扭头、翻身、点头"对应的变形。
  • t（平移向量）：负责"位置在哪"。

看到矩阵乘法，先想"基向量去哪了"，别想数字。 这是学线性代数最重要的一步。

一句话总结：矩阵 = 变形说明书（列 = 基向量去哪了）；矩阵×向量 = 按说明书变形这个向量。

1.4 矩阵乘法：两次变形合一次（相当于 3B1B 第 4 集）

1.4.1 先打比方：先穿袜子还是先穿鞋？

先穿袜子再穿鞋（正常）和先穿鞋再穿袜子（荒唐）结果完全不同。矩阵乘法也一样——顺序决定结果：

A × B ≠ B × A      （一般情况）

先做 B 的变形，再做 A 的变形 = A × B（读法：从右往左读）。

1.4.2 计算规则

| a  b |   | e  f |        | ae+bg   af+bh |
| c  d | × | g  h |   =    | ce+dg   cf+dh |

规则：结果矩阵的第 i 行第 j 列 = 左边矩阵第 i 行 × 右边矩阵第 j 列（对应相乘再相加）。

例：

| 1  2 |   | 5  6 |        | 1×5+2×7   1×6+2×8 |     | 19  22 |
| 3  4 | × | 7  8 |   =    | 3×5+4×7   3×6+4×8 |  =  | 43  50 |

1.4.3 一个有用的性质：结合律

(A × B) × C = A × (B × C)

先打包前两个，还是先打包后两个，结果一样。所以变换链可以随便"合并"：

p_world = T_wb × (T_bl × p_l) = (T_wb × T_bl) × p_l

1.4.4 和机器狗的关系：坐标变换链

机器狗身上的坐标变换是"串糖葫芦"：

点从雷达系 → 机体系 → 世界系
      ↓          ↓         ↓
    p_l     × T_bl     × T_wb

每一步都是一个矩阵乘法。外参（extrinsic）就是"雷达和机体之间"的变换 T_bl。写错顺序或写错一个数字，点云整体错位——这是你以后排查"点云错位"时第一个要怀疑的地方。

一句话总结：矩阵乘法 = 两次变形合一次；先做右边的再左边的；顺序不能换，但可以任意加括号。

1.5 三维旋转：翻身、点头、扭头（相当于 3B1B 第 5 集）

1.5.1 先打比方

飞机/机器狗的动作有三个名字：

  • roll（横滚）：绕 x 轴转——像翻身（左翻右翻）。
  • pitch（俯仰）：绕 y 轴转——像点头/抬头。
  • yaw（偏航）：绕 z 轴转——像扭头（左右看）。

机器狗走路时这三样全在动：每走一步身体都会晃（roll/pitch 小幅变化）、上下颠（高度变化）、扭（yaw 转向）。

1.5.2 绕 z 轴转 θ 度（扭头的数学）

一个点 (x, y) 绕原点逆时针转 θ 度后，新坐标是：

x' = x·cosθ − y·sinθ
y' = x·sinθ + y·cosθ

写成矩阵（就是 1.3 节的"说明书"）：

| x' |     | cosθ  −sinθ |   | x |
| y' |  =  | sinθ   cosθ | × | y |

三维绕各轴旋转矩阵（照相机视角，θ 是弧度，180° = π ≈ 3.14159）：

绕 x 轴（翻身 roll）：
| 1    0      0    |
| 0  cosθ  −sinθ  |
| 0  sinθ   cosθ  |

绕 y 轴（点头 pitch）：
|  cosθ  0  sinθ  |
|   0    1   0    |
| −sinθ  0  cosθ  |

绕 z 轴（扭头 yaw）：
| cosθ  −sinθ  0  |
| sinθ   cosθ  0  |
|  0      0    1  |

不用背，知道结构就行：对角线上有 cos，角落里有 sin，位置对应对应轴。

1.5.3 旋转矩阵的两个"身份证"

  1. 转置 = 逆：Rᵀ = R⁻¹（想转回去？把矩阵转置一下（行和列互换）就行）。
  2. 行列式 = 1（下一节讲行列式，先记住这个结论）。

1.5.4 和机器狗的关系（第 2 周主题的预告）

激光点云为什么会被"拧"坏：激光雷达不是一瞬间扫完整个环境的，一帧点云要扫几十分之一秒。这期间机器狗在晃——先采的点是在"没晃"的位姿采的，后采的点是在"晃了"的位姿采的。每个点其实用了不同的坐标系，把它们当成同一时刻拼起来，点云就扭曲了（看起来"重影"）。

补偿这个扭曲 = 把每个点按它自己的采集时刻，用对应的旋转矩阵转回同一个时刻。这就是"点云畸变补偿"，第 2 周学雅可比时你会亲手算。

一句话总结：roll/pitch/yaw = 翻身/点头/扭头；旋转 = 用 sin/cos 重算每个点的坐标；旋转矩阵转置就是逆。

1.6 行列式：变形放大了多少倍（相当于 3B1B 第 6 集）

1.6.1 先打比方：复印机

复印机有"放大 200%"档——面积变成 4 倍（长 2 倍 × 宽 2 倍）。行列式就是变形的"放大倍数"：这个变换把一块面积（二维）或体积（三维）放大了多少倍。

  • 行列式 = 2：面积放大 2 倍。
  • 行列式 = 1：面积不变（比如旋转——旋转只是转个方向，大小不变）。
  • 行列式 = 0：空间被压扁了（把平面压成一条线、把立方体压成一张纸）——信息丢了！
  • 行列式 < 0：除了放大缩小，还翻面了（镜像）。

1.6.2 怎么算

2×2：det | a  b | = a×d − b×c
         | c  d |

例：| 2  0 |     det = 2×2 − 0×0 = 4     （放大 2 倍 → 面积 ×4，对上了）
    | 0  2 |

3×3 的更复杂，Eigen 一行代码搞定（第 3 章学），本周知道含义就行。

1.6.3 和机器狗的关系

  1. 检查旋转矩阵是否合法：旋转不改变大小，所以 det(R) 必须 = 1。你写的旋转矩阵，行列式不是 1 就是写错了。
  2. "行列式 = 0" = 定位要崩：后面讲配准时，如果某个数学量（JᵀJ）的行列式接近 0，说明观测信息不够，某方向算不出来。机器狗在长直走廊里，沿走廊方向的定位信息就接近这种状态——这就是"定位退化"的数学源头。

一句话总结：行列式 = 变形的放大倍数；等于 0 = 压扁了 = 信息丢了；旋转的行列式永远是 1。

1.7 逆矩阵：撤销变形 + 解方程（相当于 3B1B 第 7、8 集）

1.7.1 先打比方：撤销键

Ctrl+Z 是"撤销上一步"。逆矩阵 = 变形的撤销键：

A⁻¹ × A = I     （A⁻¹ 读作 "A 逆"）

I 是单位矩阵（对角线全是 1、其他是 0，相当于"什么都没做"的矩阵）。

  • 先做 A 的变形，再做 A⁻¹ 的变形 = 白干 = 单位矩阵 I。
  • 转圈：先旋转 θ 度，再旋转 −θ 度，回到原点。

1.7.2 什么时候没有"撤销"？

如果 A 把平面压扁了（行列式 = 0），被压扁的点没法还原（多个点压成同一个点，不知道你原来是哪个）→ 不可逆。

所以：行列式 = 0 ⟺ 不可逆 ⟺ 信息丢失。行列式 ≠ 0 才可逆。

1.7.3 解方程 Ax = b：找"原样"是什么

方程 Ax = b 的意思是：某个向量 x 被变形 A 处理后，得到了 b。求 x 原来是什么。

  • 如果 A 可逆（没压扁）：答案唯一，x = A⁻¹ × b。
  • 如果 A 压扁了（det = 0）：
  • b 落在"压扁后的范围"里：无穷多个答案（一条线上的点都被压到同一个 b）。
  • b 落在范围外：无解。
例：| 2  1 | | x |     | 5 |        x + y ... 一个方程组的矩阵写法
    | 1 −1 | | y |  =  | 1 |

解出来 x = 2, y = 1。验证：| 2  1 | | 2 |   | 5 |
                          | 1 −1 | | 1 | = | 1 |  ✓

验证方法永远是这个：算一下 Ax，看是不是 b。

1.7.4 和机器狗的关系

SLAM 里"求解位姿"本质就是解方程。当环境退化（走廊、大平地）时，方程接近"压扁"状态（det≈0），位姿解就漂移。 你工作中遇到的"机器狗在长走廊里定位漂移"，数学根子就在这一节。

一句话总结：逆矩阵 = 撤销变形；行列式是 0 就撤不了（信息丢了）；Ax=b = 问"x 变形后是 b，x 原来是谁"。

1.8 列空间、零空间、秩：信息够不够（相当于 3B1B 第 9 集）

1.8.1 先打比方：压缩文件

把一张照片压成一条线——你失去了"宽度"信息，这条线就是列空间（变形后所有可能结果的范围）。被压到"看不见"的那部分信息，是零空间。

正式定义（配合打比方理解）：

  • 列空间：A 的所有列能拼出的所有位置 = 变形后所有可能结果的集合。Ax = b 有解 ⟺ b 在列空间里。
  • 秩（rank） = 列空间的"大小"（几维） = 变形后还剩几维。压成线 → 秩 1；完整平面 → 秩 2；压成点 → 秩 0。
  • 零空间：被 A 压到原点的所有向量。只有零向量 ⟺ 没压东西 ⟺ 信息无损。

维度定理（记住结论即可）：秩 + 零空间维度 = 列数。

1.8.2 和机器狗的关系（本周最重要的连线）

配准的最小二乘问题（第 1.14 节 SVD 会用上）解不稳定的根源：

  • 环境特征丰富（有墙、有树、有角）：信息足，秩满，位姿解稳。
  • 环境退化（长走廊、大平地、玻璃墙）：某个方向没有特征，那个方向的"秩缺了一块"（信息不够），位姿就往那个方向漂。

一句话总结：秩 = 变形后还剩几维；零空间 = 被压没的信息；走廊漂移 = 某个方向的信息秩不够了。

1.9 点积：影子的长度（相当于 3B1B 第 11 集）

1.9.1 先打比方

太阳在正上方，杆子在地上有影子。点积 = 一个向量"投在"另一个向量方向上的影子长度（× 另一个向量的长度）。

v·w = |v| × |w| × cosθ     （θ 是两个向量的夹角）

例：v = (1,0)，w = (1,1)。夹角 45°，|v|=1, |w|=√2, cos45°≈0.707
    v·w = 1 × √2 × 0.707 ≈ 1

坐标计算法（更常用，对应分量相乘再相加）：

v·w = x₁x₂ + y₁y₂ + z₁z₂
(1,0)·(1,1) = 1×1 + 0×1 = 1     ✓ 和几何算法一致

两个关键结论：

  • v·w = 0 ⟺ 两向量垂直（影子为 0）。
  • v·v = |v|²（自己点自己 = 长度平方）。

1.9.2 和机器狗的关系（本周最实用的一条）

点到平面的距离。给一面墙：墙上一点 p₀，墙的法线（垂直于墙面的方向）n。任意一点 p 到墙的距离：

距离 = | (p − p₀) · n |

激光配准（ICP/NDT）的核心残差就是它：每个激光点，找地图里最近的面，算点到面的距离，距离越小 = 位姿越准。FAST-LIO2 迭代更新时，残差计算里全是点积。看懂这一条，第 7 周配准部分就轻松一半。

一句话总结：点积 = 一个向量在另一个方向上的影子长度；垂直时点积为 0；点到面的距离就是点积。

1.10 叉积：找出"垂直的方向"（相当于 3B1B 第 12 集）

1.10.1 先打比方

两个向量确定一个平面（比如桌面上两条交叉的线）。叉积 = 垂直于这个平面的方向，用右手定则判断朝上还是朝下：右手从第一个向量弯向第二个向量，拇指指的方向就是叉积方向。

  • 大小：|v×w| = |v| × |w| × sinθ = 两个向量张成的平行四边形面积。
  • 两个向量平行时，叉积 = 0（面积 0）。

坐标公式（要会查，不用背）：

v × w = ( v₂w₃ − v₃w₂,   v₃w₁ − v₁w₃,   v₁w₂ − v₂w₁ )

1.10.2 和机器狗的关系

  1. 求墙面法向量 n：墙上两个不共线的向量做叉积，就是垂直于墙的方向——这是配准残差里"面"的来历。
  2. 旋转轴：两个向量叉积的方向 = 从第一个转到第二个的旋转轴。
  3. 刚体旋转：v = ω × r——身体上一点的速度 = 角速度 ω 叉乘位置 r。机器狗旋转导致点云畸变，补偿用的就是这个关系。

一句话总结：叉积 = 垂直于两个向量的新方向；大小 = 平行四边形面积；平行时叉积为 0。

1.11 基变换：换一把尺子（相当于 3B1B 第 13 集）

1.11.1 先打比方

同一根棍子：用米尺量 = 2 米，用英尺量 ≈ 6.6 英尺。长度没变，尺子换了，读数变了。

向量也一样：同一个点，在不同坐标系（尺子）下坐标不同。 从一套坐标换成另一套坐标，就是基变换。

数学上：

v_新坐标 = B⁻¹ × v_旧坐标     （B 的每一列 = 新坐标系基向量在旧坐标系下的坐标）
v_旧坐标 = B × v_新坐标

简单理解：乘以"换尺子矩阵" = 把读数换算成另一把尺子的读数。

1.11.2 和机器狗的关系（这就是"外参"的全部内容）

机器狗有雷达坐标系、机体坐标系、世界坐标系。每两套坐标之间都有一个"换尺子矩阵"，这就是外参和位姿。

  • extrinsic_T（平移）= 两个坐标系原点差多远。
  • extrinsic_R（旋转）= 两个坐标系的轴差多少角度。

前后两个雷达各有一个外参。外参写错 → 点云错位。你排查"点云错位"问题时，第一步就要怀疑外参。

一句话总结：基变换 = 换把尺子量同一个东西；外参 = 两套坐标之间的换尺子矩阵。

1.12 特征值与特征向量：变形中不动的方向（相当于 3B1B 第 14 集）

1.12.1 先打比方

把一张世界地图横向拉长 2 倍：正东方向的线只被拉长、方向没变；斜着的线方向和长度都变了。

  • 特征向量 = 变形后方向不变的那些方向（正东那条线）。
  • 特征值 = 这个方向被拉长了多少倍（2 倍）。

数学定义：

A × v = λ × v

A 对 v 做变形，结果只是把 v 拉长了 λ 倍（方向没变）。v 是特征向量，λ 是特征值。

例：| 2 0; 0 3 | 把平面横向拉 2 倍、纵向拉 3 倍。特征向量 (1,0)（横向）特征值 2；(0,1)（纵向）特征值 3。

1.12.2 和机器狗的关系

  1. 误差椭球：定位的不确定性是个"椭圆"，椭圆的长轴方向 = 特征向量，长轴长度 = 特征值。特征值最大的方向 = 最没把握的方向。
  2. 退化检测：某个特征值接近 0 = 那个方向几乎没有信息 = 不能信那个方向的定位。机器狗进走廊时，沿走廊方向的定位不确定性会变大——这是正常现象，程序要能"知道"并降级处理。

一句话总结：特征向量 = 变形后方向不变的线；特征值 = 那条线被拉长几倍；特征值 ≈ 0 的方向 = 信息缺失的方向。

只要一套东西满足"能加、能缩放"，线性代数的一切工具就能用在它身上。函数、信号、多项式都能当"向量"用。

  • 例：一段声音信号可以分解成一堆正弦波（傅里叶）——正弦波就是"声音空间的基"。
  • 本周知道"向量不只是一列数字"就够了，不深究。

一句话总结：向量 = 任何"能加、能缩放"的东西，不一定是箭头。

1.14 SVD：把任何变形拆成"转—拉—转"（相当于 3B1B 第 16 集）

1.14.1 先打比方：任何复杂的变形都能拆成三步

不管多复杂的变形（挤压、剪切、倾斜……），都可以看成：

变形 = 先转一个角度（Vᵀ）→ 再沿坐标轴拉长/缩短（Σ）→ 最后再转一个角度（U）

数学上写成：

A = U × Σ × Vᵀ
  • U、V：旋转矩阵（正交矩阵）。
  • Σ：对角矩阵，对角上的数 σ₁ ≥ σ₂ ≥ … ≥ 0 叫奇异值（就是"拉长了多少倍"的倍数）。

关键事实：

  • 奇异值有几个非零 = 秩是几（信息剩几维）。
  • 最小奇异值接近 0 = 某个方向被压扁 = 退化。
  • 伪逆：不可逆/非方阵的矩阵也有"几乎逆"：A⁺ = V × Σ⁺ × Uᵀ（Σ⁺ 把非零奇异值取倒数）。用它求最小二乘解：找不到精确解时，找"误差最小的解"。

1.14.2 和机器狗的关系（本周最重要的应用：Kabsch 算法）

已知两帧点云里的点一一对应（比如都是墙上的同一排钉子），求机器人转了多少、移了多少？

解法（Kabsch 算法，ICP 配准的核心）：

1. 两帧点都减去各自中心（去掉平移的影响）
2. 算 H = P' × Q'ᵀ（“两帧有多像”的矩阵）
3. 对 H 做 SVD：H = U × Σ × Vᵀ
4. 旋转 = V × Uᵀ，平移 = Q的中心 − R × P的中心

周六实验你要亲手写这个算法，要求误差 < 1e-10。它就是你以后工作中"点云配准对齐两帧"的最基本工具。

一句话总结：SVD = 把任何变形拆成"旋转—拉伸—旋转"；奇异值接近 0 = 退化；Kabsch 用 SVD 从两帧对应点反推出旋转和平移。

2.0 预备：程序 = 菜谱

程序就是给计算机的菜谱：一系列步骤，按顺序执行。C++ 程序的骨架：

#include <iostream>              // 准备工具：输入输出

  • 每条语句以 ; 结尾（就像句子以句号结尾）。

2.1 变量：贴了标签的盒子（覆盖 Primer 第 2 章）

变量 = 一个存数的盒子，盒子上有名字标签。

double x = 0.0;      // 一个叫 x 的盒子，里面放 0.0（double = 带小数的数）
int    n = 3;        // 一个叫 n 的盒子，放整数 3（int = 整数）
bool   ok = true;    // true/false = 对/错
类型 能存什么 例子
int 整数 点数、循环次数
double 带小数的数 位置、速度、距离
bool 对/错 是否初始化
float 带小数的数（精度低） 点云坐标（省内存）
string 文字 话题名、文件名

为什么机器人代码几乎全用 double：SLAM 里差 0.0000001 就可能让结果跑偏。double 比 float 精确得多。看到 float 要警惕精度损失。

const 标签：盒子上贴"只读，不许改"：

const double g = 9.81;      // 重力加速度，永远不许改

规则：盒子一定要先放东西再使用（没放东西的盒子叫"未初始化"，里面是垃圾值）。Eigen 矩阵默认就是"没放东西的盒子"——所以到处要 .setZero()（第 3 章）。

两个变量可以"共用同一个盒子"（引用，第 2.5 节讲）。

2.2 判断与循环：岔路口和绕圈（覆盖 Primer 第 4、5 章）

if = 岔路口：

double dist = 3.5;
if (dist > 2.0) {          // 如果 dist 大于 2.0
    std::cout << "太远了" << std::endl;
} else {                   // 否则
    std::cout << "可以" << std::endl;
}

注意：== 是"等于"，= 是"赋值"。if (x = 1) 是把 1 塞进 x（恒为真，Bug！），if (x == 1) 才是判断。

for = 绕圈：

for (int i = 0; i < 5; ++i) {     // 从 0 数到 4，共 5 次
    std::cout << i << std::endl;
}

读法：初始 i=0 → 检查 i<5 → 干活 → i 加 1 → 再检查… 直到 i=5 不满足条件停。

while = 只要条件成立就一直绕：

while (has_data()) {      // 只要有数据就一直处理
    process();
}

break / continue：

for (...) {
    if (太远) continue;    // 跳过这一圈，进入下一圈
    if (结束) break;       // 跳出整个循环
    ...
}

经典读码技巧：看到 if 问"过滤掉了什么？"看到 for 问"在遍历谁？"——FAST-LIO2 预处理里大量 if 就是在问"这个点要不要"。

2.3 vector：会变长的货架（覆盖 Primer 第 3 章）

vector = 一排放东西的货架，可以随时往后面加。点云就是一个 vector，每个格子放一个点。

#include <vector>
std::vector<double> v;            // 一个空的货架
v.push_back(1.0);                 // 往末尾放 1.0
v.push_back(2.5);                 // 再放 2.5
v.size();                         // 现在有几格（2）
v[0];                             // 第 0 格的内容（1.0）——注意从 0 开始数！
v.at(0);                          // 同上，但越界会报错（开发时好用）
v.clear();                        // 清空货架

坑：v[99] 越界不会报错（未定义行为），可能程序悄悄错。调试期用 .at()。

遍历 = 把货架从头到尾看一遍（两种写法）：

// 写法1：用下标
for (int i = 0; i < v.size(); ++i) {
    std::cout << v[i] << std::endl;
}

// 写法2：范围 for（更常用）
for (const auto& x : v) {         // 逐个取出，叫 x
    std::cout << x << std::endl;
}

读法：for (const auto& x : v) = "对 v 里的每个元素 x（只读、不拷贝）做…"。

为什么写 const auto&： - auto = 让编译器自动猜类型（省得你写长类型名）。 - & = 引用（借用，不复制）。不复制 = 快（点云有几万个点，复制一次很慢）。 - const = 只读（保证遍历时不乱改）。

FAST-LIO2 里 for (const auto& p : pc) 出现几十次——看到这个就知道：在遍历点云，只读每个点。

2.4 函数：给一段步骤起个名字（覆盖 Primer 第 6 章）

函数 = 给一段"菜谱步骤"起名字，以后叫名字就能用。

// 定义：一个叫 distance 的函数，输入两个点，输出距离
double distance(double x1, double y1, double x2, double y2) {
    double dx = x2 - x1;
    double dy = y2 - y1;
    return sqrt(dx*dx + dy*dy);      // return = 把结果交出去
}

// 使用
double d = distance(0, 0, 3, 4);     // 调用：输出 5

结构：返回类型 函数名(参数列表) { 函数体 }。

参数传递三条规则（看代码时必须懂）： 1. 小东西（int、double）：直接传值（复印一份）。 2. 大东西（点云、矩阵）：用 const 类型& 传——只借不复印（快、还保证不改）。 3. 需要修改外面变量的：用 类型&（借走并允许改）。

重载 = 同一个名字、不同参数：

double area(double r);              // 算圆面积
double area(double w, double h);    // 算矩形面积
// 调用 area(1.0) 选第一个，area(1.0, 2.0) 选第二个

2.5 引用与 const：借东西，不复印

double v = 1.0;
double& ref = v;        // ref 是 v 的"另一个名字"——同一个盒子
ref = 2.0;              // 改 ref 就是改 v（v 现在也是 2.0）
  • 引用 &：给同一个盒子起别名。改谁都一样。
  • 指针 *：盒子的"门牌号"（地址）。double* p = &v; 存 v 的地址；*p 是"走到门牌号那，打开盒子"。
  • const&：借来看，不许改，也不复制。

机器狗场景：点云有几万几十万个点。函数接收点云时如果"复印一份"，每帧都要复制，又慢又占内存。所以一律"借"——const std::vector<PointType>& cloud 的意思："借你的点云看看，不复制，也不改"。

2.6 lambda：顺手写的小函数（覆盖 Primer 第 6 章 lambda）

lambda = 不单独起名字、当场写出来的小函数。格式：

[捕获]（参数）{ 函数体 }

// 例：按强度从小到大排序（sort 需要一个"谁小谁在前"的规则）
std::sort(points.begin(), points.end(),
          [](const PointType& a, const PointType& b) {
              return a.intensity < b.intensity;
          });
  • [] 里写"捕获"：lambda 想用外面定义的变量，[=] 按值拷贝，[&] 用引用，[threshold] 只拷贝这一个。

机器狗场景：点云要按时间戳排序（去畸变前提）——sort 配 lambda 就是这个用途，你在 preprocess 里会亲眼看到。

3.1 Eigen 是什么

Eigen 是一个 C++ 数学库——别人帮你写好的"向量、矩阵、解方程"工具，你直接调用。它是纯头文件库（不用编译、不用链接），在 CMake 里一行配置就能用。

3.2 创建矩阵和向量（覆盖 Eigen Matrix class）

#include <Eigen/Dense>

Eigen::Matrix3d A;        // 3×3 的矩阵（double 类型）
Eigen::Vector3d v;        // 3 维向量（3×1 的矩阵）

// 初始化：逗号初始化（一行一行填）
A << 1, 2, 3,
     4, 5, 6,
     7, 8, 9;

// 特殊矩阵
Eigen::Matrix3d Z = Eigen::Matrix3d::Zero();       // 全 0
Eigen::Matrix3d I = Eigen::Matrix3d::Identity();   // 单位矩阵（对角线 1）
Eigen::Vector3d b(1.0, 2.0, 3.0);                  // 直接给值

// 访问元素（用圆括号！）
A(0, 0);      // 第 0 行第 0 列 = 1

3.3 基本运算

Eigen::Vector3d y = A * v;            // 矩阵 × 向量
Eigen::Matrix3d P = A * B;            // 矩阵乘法
A.transpose();                        // 转置（行列互换）
A.determinant();                      // 行列式
v.norm();                             // 向量的长度（模长）
v.dot(w);                             // 点积
v.cross(w);                           // 叉积
A.inverse();                          // 逆矩阵（验证用！）

3.4 解方程 Ax = b（唯一正确姿势）

Eigen::Matrix3d A;
A << 2, 1, -1,
    -3, -1, 2,
    -2, 1, 2;
Eigen::Vector3d b(8, -11, -3);

Eigen::Vector3d x = A.colPivHouseholderQr().solve(b);   // 用 QR 分解解方程
std::cout << (A * x - b).norm() << std::endl;           // 验证：应 ≈ 0

铁律：解方程不要用 A.inverse()（慢、不稳定）。用 .solve(b)。inverse() 只用于数学验证。

3.5 SVD 和特征值

// SVD：A = U × Σ × Vᵀ
Eigen::JacobiSVD<Eigen::Matrix3d> svd(A, Eigen::ComputeFullU | Eigen::ComputeFullV);
svd.singularValues();       // 奇异值（降序）
svd.matrixU();              // U
svd.matrixV();              // V

// 特征值（对称矩阵用）
Eigen::SelfAdjointEigenSolver<Eigen::Matrix3d> es(A);
es.eigenvalues();           // 特征值
es.eigenvectors();          // 特征向量

3.6 旋转（绕 z 轴转 45°）

#include <Eigen/Geometry>

Eigen::AngleAxisd rot(45.0 * 3.14159265 / 180.0, Eigen::Vector3d(0, 0, 1));
Eigen::Matrix3d R = rot.toRotationMatrix();   // 转成 3×3 旋转矩阵

3.7 三个必须背的坑

  1. 矩阵默认不初始化——用 << 或 ::Zero()。
  2. auto 陷阱：auto B = A.transpose(); 得到的是"临时表达式"，可能出 bug。要写成 Eigen::Matrix3d B = A.transpose();。
  3. 解方程用 .solve()，不用 .inverse()。

流程（大白话版）：

原始点云（一帧帧到来，每帧只有几十个点）
   │
   ▼
① 按雷达型号分流（不同雷达处理方式不同）
   │

5.4 任务 3：SVD 验证 + 用 SVD 反推旋转（Kabsch）（50 分钟）

// Step A：SVD 验证（奇异值应为 2, 1, 0）
Eigen::Matrix3d M;
M << 1, 0, 0,
     0, 2, 0,
     0, 0, 0;
Eigen::JacobiSVD<Eigen::Matrix3d> svd(M, Eigen::ComputeFullU | Eigen::ComputeFullV);
std::cout << "奇异值: " << svd.singularValues().transpose() << "\n";

// Step B：Kabsch——给两组对应点，求旋转
Eigen::Matrix3Xd P(3, 5);
P << 1, 2, 3, 4, 5,
     0, 1, 0, 1, 0,
     0, 0, 1, 1, 2;

Eigen::AngleAxisd angle(0.3, Eigen::Vector3d(0, 0, 1));   // 真实旋转：绕 z 转 0.3 弧度
Eigen::Matrix3d R_true = angle.toRotationMatrix();
Eigen::Matrix3Xd Q = R_true * P;                          // Q = 旋转后的点

// 现在只知道 P 和 Q，假装不知道旋转，把它算出来：
Eigen::Vector3d p_mean = P.rowwise().mean();              // 1. 去中心
Eigen::Vector3d q_mean = Q.rowwise().mean();
Eigen::Matrix3d H = (P.colwise() - p_mean) * (Q.colwise() - q_mean).transpose();
Eigen::JacobiSVD<Eigen::Matrix3d> svd2(H, Eigen::ComputeFullU | Eigen::ComputeFullV);
Eigen::Matrix3d R_est = svd2.matrixV() * svd2.matrixU().transpose();   // R = V×Uᵀ

std::cout << "误差 = " << (R_est - R_true).norm() << "\n";  // 应 < 1e-10
