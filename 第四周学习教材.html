0.3 本周主线问题

"让误差最小"这件事，数学上怎么做？ —— 从一个初始猜测出发，反复"算误差 → 求改进方向 → 迈一小步"，直到误差不再变小。这就是本周全部内容。

第 1 章 优化：找"最好"的数学

1.0 预备：最小二乘是什么

1.0.1 先打比方：拟合直线

给你一堆点（身高 vs 体重），想画一条直线 y = kx + b 描述规律。哪条线最好？"每个点到直线的距离加起来最小"的那条。

误差函数（代价函数）：E(k, b) = Σ (预测值 − 真值)²
每个点：预测值 = k·x + b，真值 = y

"每个误差平方后求和" = 最小二乘（平方 = 二乘）。为什么平方？① 正负不抵消；② 误差大的惩罚更重；③ 和"噪声是高斯"的假设完美匹配（高斯噪声下，最小二乘 = 最可能）。

1.0.2 和机器狗的关系

SLAM 里几乎所有"求解"都是最小二乘：

问题 误差是什么 要优化的变量
曲线拟合 点到曲线距离 k, b
点云配准 点到面距离（第 1 周学过！） 位姿 R, t
双雷达标定 同一特征点投影差 外参
回环优化 同一位置两次观测的差 所有位姿

一句话总结：最小二乘 = 找让"误差平方和"最小的参数；SLAM 的求解基本全是它。

1.1 Gauss-Newton：迭代下山（本周核心）

1.1.1 先打比方：蒙眼下山

你站在山上（误差大），想走到谷底（误差最小），但看不见路。怎么办？——感受脚下的坡，往"下坡"方向迈一步，再感受，再迈一步。反复走，直到脚下是平的。

  • 方向 = 误差函数的"坡度"（导数/雅可比）。
  • 步长 = 怎么决定走多大？Gauss-Newton 用二阶信息（雅可比平方）估算"谷底在哪"，直接一步跳向估算的谷底。

1.1.2 数学（记住思路，公式能对照代码即可）

目标：min ‖f(x)‖²（f = 残差向量）。

泰勒展开（把 f 在 x 附近展开成线性近似）：

f(x + Δx) ≈ f(x) + J·Δx        （J = 雅可比矩阵，第 2 周学的！）

把近似代入误差函数，对 Δx 求导置零，得到增量方程：

(JᵀJ)·Δx = −Jᵀ·f
       ↑         ↑
   信息矩阵     右端项（梯度方向）

算法循环：

1. 算残差 f（当前参数下，误差是多少）
2. 算雅可比 J（参数变一点，残差变多少）
3. 解增量方程 (JᵀJ)Δx = −Jᵀf，得到改进方向 Δx
4. 更新：x ← x + Δx
5. 重复，直到 Δx 很小（收敛）或达到迭代上限

1.1.3 数字例子：拟合直线（跟着算一遍）

数据：点 (1,2)、(2,3)、(3,5)。模型 y = kx + b，要优化 x = (k, b)。

  • 残差：r₁ = k·1+b−2，r₂ = k·2+b−3，r₃ = k·3+b−5。
  • 初始猜：k=0, b=0。
  • 雅可比 J（对 k、b 求偏导）：第 i 行 = (xᵢ, 1)：
J = | 1  1 |
    | 2  1 |
    | 3  1 |
  • 残差 f = (−2, −3, −5)。
JᵀJ = | 14  6 |      Jᵀf = | −23 |
       |  6  3 |            | −10 |
解 (JᵀJ)Δx = −Jᵀf：
| 14  6 | |Δk|   | 23 |
|  6  3 | |Δb| = | 10 |
→ Δk ≈ 1.5, Δb ≈ 0.33
更新：k = 1.5, b = 0.33

继续迭代（代码里让循环做），最终收敛到 k≈1.5, b≈0.5（验证：y = 1.5x + 0.5，三个点残差 −0.5、0.5、0）。

一句话总结：Gauss-Newton = 反复"算残差+雅可比 → 解增量方程 → 更新"，误差逐步变小直到收敛。增量方程里的 JᵀJ 叫信息矩阵。

1.2 Levenberg-Marquardt（LM）：给下山加"刹车"

1.2.1 问题

Gauss-Newton 步子太自信（直接跳向估算谷底）。如果初始猜测离谷底太远、或雅可比不准，可能跳过头甚至发散。怎么防？

LM = 在增量方程里加一个"阻尼项"：

(JᵀJ + λ·I)·Δx = −Jᵀf
       ↑
    阻尼系数 λ（刹车）
  • λ 大：方程接近 (λI)Δx = −Jᵀf → Δx 指向"最陡下坡"方向（梯度下降，保守、慢、稳）。
  • λ 小：方程接近 Gauss-Newton（快、自信）。
  • 自适应：如果这一步让误差变小 → λ 减小（放心大步走）；误差变大 → λ 增大（刹车，退回）。

比喻：GN 是闭眼直冲，LM 是"冲一步看看，歪了就刹"。实际工程几乎都用 LM（Ceres 默认）。

1.2.2 和机器狗的关系

FAST-LIO2 的迭代更新本质就是 LM/GN 思想（在流形上迭代）。Ceres（谷歌的开源优化库）是工业级实现——你不需要自己写矩阵求解，Ceres 全包。

一句话总结：LM = GN + 阻尼 λ；误差变小就松刹车，变大就踩刹车；实际工程默认用 LM。

1.3 信息矩阵与协方差的关系

1.3.1 概念

  • 协方差 Σ：不确定度（大 = 没把握）。第 3 周学过。
  • 信息矩阵 = 协方差的逆：Λ = Σ⁻¹（大 = 信息多 = 有把握）。

JᵀJ 为什么叫信息矩阵：在最小二乘里，(JᵀJ)⁻¹ ≈ 估计的协方差——JᵀJ 越"大"（特征值大），说明这个方向信息越多，估计越准。这和退化判断对上了（第 1 周：JᵀJ 行列式小 = 退化）。

1.3.2 和机器狗的关系

  • 定位结果输出"位姿 + 协方差"——协方差就是这么来的（配准问题解完，JᵀJ 求逆）。
  • 退化检测：算 JᵀJ 的最小特征值，太小就报警"这个方向不可信"。

一句话总结：信息矩阵 = 协方差的逆；JᵀJ 特征值小 = 那个方向信息不足 = 定位退化。

1.4 Ceres：开箱即用的优化库（覆盖 Ceres 教程任务）

1.4.1 Ceres 是什么

Ceres = 谷歌开源的 C++ 优化库：你只要告诉它"残差怎么算、参数是什么"，它自动做 GN/LM 迭代。SLAM 里几乎所有开源项目（FAST-LIO2 的兄弟项目、VINS、部分建图工具）都用它。

1.4.2 最小用法：曲线拟合（本周任务）

#include <ceres/ceres.h>
#include <iostream>

// ① 定义"残差"：一个点产生的误差
struct LineResidual {
    double x, y;
    LineResidual(double xx, double yy) : x(xx), y(yy) {}

    // 模板函数：计算残差（Ceres 自动求导用）
    template <typename T>
    bool operator()(const T* k, const T* b, T* residual) const {
        residual[0] = k[0] * x + b[0] - y;   // kx + b - y
        return true;
    }
};

int main() {
    // ② 数据：三个点
    double pts[][2] = {{1, 2}, {2, 3}, {3, 5}};

    // ③ 初始猜测
    double k = 0.0, b = 0.0;

    // ④ 建问题：把每个残差加进去
    ceres::Problem problem;
    for (auto& p : pts) {
        problem.AddResidualBlock(
            new ceres::AutoDiffCostFunction<LineResidual, 1, 1, 1>(
                new LineResidual(p[0], p[1])),
            nullptr, &k, &b);
    }

    // ⑤ 求解（默认 LM）
    ceres::Solver::Options options;
    options.linear_solver_type = ceres::DENSE_QR;
    ceres::Solver::Summary summary;
    ceres::Solve(options, &problem, &summary);
    std::cout << summary.BriefReport() << "\n";
    std::cout << "k = " << k << ", b = " << b << "\n";   // ≈ 1.5, 0.5
    return 0;
}

三段式：定义残差 → 加入问题 → 求解。以后你写任何"拟合/标定/配准"任务都是这个套路。

1.4.3 概念映射（Ceres 语言 ↔ 数学语言）

Ceres 概念 数学概念 大白话
ResidualBlock 残差项 f 一条"误差"
AutoDiffCostFunction 自动求雅可比 不用手写导数，Ceres 自动算
ParameterBlock 变量 x 要优化的量（k, b, 位姿）
Solver 求解器 自动迭代
LossFunction（nullptr 处） 鲁棒核 抗"野点"（下面讲）

鲁棒核（LossFunction）：数据里有一两个"野点"（严重错误测量），平方误差会把优化拉偏。鲁棒核 = "误差大到一定程度不再重罚"，让野点影响变小。实际配准/标定必须加（如 new ceres::HuberLoss(1.0)）。

一句话总结：Ceres = 三段式（定义残差 → 加进问题 → 求解）；自动求导不用手写雅可比；野点多要加鲁棒核。

1.5 系统化调试五步法（本周核心技能，记住！）

这是你三个月里排查一切 Bug 的骨架。每个 Bug 案例都用它。

1.5.1 五步（实际是七步，两步合并理解）

① 复现（Reproduce）
   让 Bug 稳定出现。不能稳定复现的问题没法查。
   → 录 bag、写最小复现脚本、记下触发条件

② 最小化（Minimize）
   把无关因素全砍掉：只留最必要的环节。
   → 关掉不相关的节点、用固定数据、删掉花哨功能

③ 二分定位（Bisect）
   在链路中间切开：上面好还是下面好？每次砍一半。
   → 看数据流："断在哪一段"（rqt_graph 看链路，topic hz 看数据）

④ 假设 → 验证（Hypothesize & Verify）
   提出可能原因（1 个或多个），设计实验验证，逐个排除。
   → 改参数试、加打印、看日志、对照源码

⑤ 修复 → 回归（Fix & Regression）
   修复后验证：Bug 没了，且原有功能没坏。
   → 跑一遍原场景 + 相邻场景

1.5.2 和机器狗工作结合

现象 第一步 常用工具
导航不动 复现：录 bag + 触发条件 ros2 bag、rqt_graph
定位漂移 最小化：只开 SLAM，关导航 PlotJuggler 看轨迹
点云错位 二分：单雷达 vs 双雷达 分别看两路点云
速度突跳 假设验证：停掉 smoother 试试 参数开关

1.5.3 写 Bug 案例的时机

每个 Bug 修完，立刻按模板记录（现象/复现/根因/修复/验证/可复用经验）——三个月攒 12 个，就是你的"排查手册"。

一句话总结：调试五步 = 复现 → 最小化 → 二分 → 假设验证 → 修复回归。所有 Bug 排查都走这个流程。

第 2 章 ROS2 进阶

2.0 Action：可取消的长任务（覆盖 action 任务）

2.0.1 为什么需要

话题（广播）没有"完成没完成"；服务（问答）不能取消。导航到某个点 = 长任务（可能 10 秒，可能失败）——需要：开始、进度回报、可取消。这就是 action。

客户端（导航请求方）          服务端（导航执行方）
  |-- 发送目标(Goal) -----------→|
  |←---- 反馈(Feedback) ---------|  （“走了 30%...”）
  |←---- 结果(Result) -----------|  （“到达了！”）
  |-- 取消(Cancel) -------------→|  （“算了，停下来”）

Nav2 的导航动作：NavigateToPose——它的 Goal = 目标坐标，Feedback = 进度，Result = 成败。这是你以后调导航时最常见的 action。

2.1 QoS 与 Lifecycle（覆盖概念任务）

2.1.1 QoS：数据的"服务质量"契约

发布者和订阅者要谈好"怎么传数据"，否则连不上。关键设置：

QoS 含义 用在哪
Reliability 可靠（丢了重发）/ 尽力（丢了不管） 控制指令必须可靠；点云可尽力
Durability 消息存不存（新订阅者能不能拿到旧数据） 地图/TF 静态变换要"存"
History/Depth 缓存多少条 内存 vs 完整

经典 Bug：两个节点连不上（subscription ... offered incompatible QoS）——多半是 QoS 没谈拢。修法：对齐双方设置。

2.1.2 Lifecycle：节点的"开关机状态机"

普通节点只有"运行"。Lifecycle 节点有状态：

Unconfigured → Inactive → Active → Finalized
   （未配置）   （配置好没开工）（干活中）   （清理）

为什么需要：传感器/导航节点要按顺序启动（先配参数 → 再开跑）。Nav2 的节点几乎全是 lifecycle 节点——导航时"节点 Inactive/Active"的变化就是状态机在走。命令行 ros2 lifecycle get /节点名 查看。

2.4 Nav2 插件机制（覆盖"插件教程"任务）

2.4.1 插件是什么

插件 = 可插拔的算法模块。Nav2 的规划器/控制器/层都是插件：想换一种算法，不用改主程序，配置里换个插件名即可。

2.4.2 插件怎么注册（读 inflation layer 源码时对照）

pluginlib 机制三步：
① 写算法类，继承基类（如 nav2_costmap_2d::Layer）
② 注册宏：PLUGINLIB_EXPORT_CLASS(类名, 基类)
③ 声明 XML：告诉系统"这个名字 → 这个类"

inflation layer 里你会看到（inflation_layer.hpp 底部）：

PLUGINLIB_EXPORT_CLASS(
    nav2_costmap_2d::InflationLayer, nav2_costmap_2d::Layer)

这行的意思："把 InflationLayer 注册成 Layer 插件"。配置 yaml 里写 plugin: "nav2_costmap_2d::InflationLayer" 就能加载。

第 12 周最终项目之一 = 写一个自定义 controller 插件——你到时会完整走一遍这三步。

一句话总结：插件 = 可插拔算法模块；三步注册（继承 → 导出宏 → XML 声明）；Nav2 的规划/控制/图层全是插件。

4.1 任务 1：曲线拟合三版对比（90 分钟，核心交付）

同一组数据（带噪声的抛物线点），用三种方法拟合，输出误差对比表：

数据（Python 生成，存 csv）：

import numpy as np
np.random.seed(1)
x = np.linspace(-2, 2, 20)
y = 0.5*x*x + 1.0 + np.random.normal(0, 0.3, 20)   # 真模型：y = 0.5x² + 1
np.savetxt('data.csv', np.column_stack([x, y]), delimiter=',')

版本 1：手写 GN（Python，按 1.1 节公式）：

import numpy as np
data = np.loadtxt('data.csv', delimiter=',')
x, y = data[:, 0], data[:, 1]

# 模型 y = a*x² + b，参数 [a, b]，残差 r = a*x² + b - y
a, b = 0.0, 0.0
for it in range(20):
    r = a*x**2 + b - y                       # 残差
    J = np.column_stack([x**2, np.ones_like(x)])  # 雅可比（对 a、b 求偏导）
    H = J.T @ J                               # JᵀJ（信息矩阵）
    g = J.T @ r                               # Jᵀf
    delta = np.linalg.solve(H, -g)            # 解增量方程
    a += delta[0]; b += delta[1]
    print(f"iter {it}: a={a:.4f}, b={b:.4f}, cost={np.sum(r**2):.4f}")
print("GN 结果:", a, b)                       # 应 ≈ 0.5, 1.0

版本 2：手写 LM（把 H 换成 H + λI，自适应 λ）：

a, b, lam = 0.0, 0.0, 1e-3
cost = np.inf
for it in range(50):
    r = a*x**2 + b - y
    J = np.column_stack([x**2, np.ones_like(x)])
    H = J.T @ J; g = J.T @ r
    delta = np.linalg.solve(H + lam*np.eye(2), -g)
    a2, b2 = a + delta[0], b + delta[1]
    cost2 = np.sum((a2*x**2 + b2 - y)**2)
    if cost2 < cost:           # 变好了：接受，松刹车
        a, b, cost = a2, b2, cost2
        lam *= 0.7
    else:                      # 变差了：拒绝，踩刹车
        lam *= 2.0
print("LM 结果:", a, b)

版本 3：Ceres（按 1.4 节模板，拟合 y = a·x² + b）。

输出对比表：

方法 收敛结果 a b 迭代次数 收敛时成本
手写 GN
手写 LM
Ceres

✅ 三种方法结果应一致（≈0.5, ≈1.0），LM 和 GN 迭代次数可不同。提交 git。
