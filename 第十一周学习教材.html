第 1 章 局部规划器：每秒该给多少速度

1.0 DWA（动态窗口法）：在"能刹住"的范围里挑最好的

1.0.1 思想（先打比方）

开车时你每秒做决定：往左打一点？踩油门？——但你不可能试所有可能，只能试"下一个瞬间能做到的"选项，挑一个"又快又安全又顺着路"的。

DWA 就是这个思路，分三步：

1.0.2 三步

① 速度空间采样：列出"此刻可能的速度组合"
   （线速度 v ∈ [0, v_max]，角速度 ω ∈ [−ω_max, ω_max]）
   但要"能刹住"：按当前速度 + 刹车距离筛选（动态窗口！）

② 模拟轨迹：对每个候选 (v, ω)，模拟一小段未来的轨迹（0.1~1 秒）

③ 评价打分：给每条轨迹打分：
   评分 = w₁·目标朝向 + w₂·路径贴合 + w₃·障碍距离 + w₄·速度
   选总分最高的 (v, ω) 发出去

1.0.3 评价函数（读源码时找的就是它）

评分 = 对齐度（朝目标/路径的方向有多对）
     + 贴合度（离全局路径多近）
     + 安全度（离障碍多远）
     + 前进度（速度多快）
四个权重 w₁~w₄ 就是 DWA 的全部"性格"：
   w₂ 大 = 死贴路径（可能擦障碍/绕远）
   w₃ 大 = 怂（离障碍八丈远，可能钻不过窄缝）

1.0.4 优缺点

优点 缺点
简单、快、好理解 视野短（只模拟 1 秒）
实时避障 窄通道/复杂环境容易卡
参数直观 默认"只看脚下"，容易忽略全局

一句话总结：DWA = 每秒"采样速度 → 模拟轨迹 → 打分 → 发最好的"；四个权重决定性格（贴路径/怕障碍/求快）。

1.1 TEB：把"一段时间的轨迹"整体优化

1.1.1 思想（和 DWA 的根本区别）

DWA 只考虑"接下来 1 秒"；TEB 优化"接下来几秒的一条完整轨迹"（一串位姿点 + 每段的时间），用一个优化问题整体求解：

TEB 要优化的东西：
轨迹点序列：P₀, P₁, P₂, ..., Pₙ
每段时间：Δt₀, Δt₁, ...

目标函数（最小化）：
① 时间最优：总时间越短越好（走得快）
② 贴合路径：别离全局路径太远
③ 障碍惩罚：离障碍越远越好
④ 运动学约束：速度/加速度/曲率不超限
⑤ 平滑：轨迹别扭

1.1.2 TEB vs DWA

DWA TEB
视野 1 秒（短） 几秒（长）
求解 采样打分 优化（第 4 周学的 GN/LM 框架）
窄通道 容易卡 更擅长（看得远）
调参 权重 4 个 权重更多，更敏感
计算 轻 重一些

为什么叫"时间最优"：TEB 连"每段走多久"一起优化——它能"权衡"是该快点冲过去还是慢点绕开。

1.1.3 关键参数（周二读文档时查）

dt_ref / dt_hysteresis:  期望的时间步长（默认 0.3s）
weight_obstacle:         障碍权重（大 = 离障碍远）
weight_time_optimal:     时间权重（大 = 走快）
weight_kinematics:       运动学约束权重
max_vel_x / max_vel_theta: 速度上限
penalty_epsilon:         障碍惩罚的"软边界"

一句话总结：TEB = 把"几秒内的轨迹+时间"整体优化（时间最优+避障+约束）；看得比 DWA 远，窄通道更擅长，但参数更敏感。

1.2 Pure Pursuit 与 MPC（F1TENTH 补充，周三）

1.2.1 Pure Pursuit（纯跟踪）：追着一个"前方的点"走

最简单实用的控制器：在路径上找一个"前方 lookahead 距离"的点，然后算"怎么转向才能追上它"：

原理：把机器人当前朝向与"前方点"之间的角度差，转成转向指令
关键参数：lookahead 距离（看多远）
  lookahead 大 = 转弯慢而稳（提前转）
  lookahead 小 = 转弯灵活但抖动

适合：高速、平滑路径；不适合：复杂避障。

1.2.2 MPC（模型预测控制）：用模型"预演未来"再决策

MPC = 用系统模型，反复预测未来 T 步，优化每一步的控制量，但只执行第一步，然后重来：

每个控制周期：
1. 用运动模型预测未来 T 步（输入候选控制序列）
2. 优化：让预测轨迹满足目标（跟路径、避障、省力）
3. 只执行第一个控制量
4. 下一周期重复（滚动时域）

MPC vs TEB：TEB 是"纯路径优化"；MPC 是"控制层面的优化"（直接出控制量、处理输入输出约束）。四足领域 MPC 常用于步态控制（腿怎么迈），对导航来说 MPC 计算量大。

1.2.3 周三输出：DWA vs TEB vs MPC 对比表

| 维度 | DWA | TEB | MPC |
| 视野 | 1s | 几秒 | T 步（可长可短） |
| 方法 | 采样打分 | 轨迹优化 | 预测控制优化 |
| 窄通道 | 弱 | 强 | 强 |
| 计算量 | 轻 | 中 | 重 |
| 调参难度 | 低 | 中高 | 高 |
| 四足适配 | 常用 | 常用 | 控制层用（步态） |
| 我选（场景） | 简单环境 | 复杂环境 | 研究/控制层 |

一句话总结：pure pursuit = 追前方点（简单快）；MPC = 用模型预演未来选最优控制（最强最重）；DWA/TEB 是导航常用的两个。

1.3 四足运动约束与速度平滑（周四）

1.3.1 四足速度约束（比轮式多一层）

轮式：v_max / ω_max / 加速度限制
四足：还要加：
- 步态相关：小跑能 2m/s，慢走只能 0.5m/s，爬行更慢
- 加速度限制：起步/刹车太猛 = 狗要踉跄（步态跟不上）
- 转向限制：高速时不能急转（会侧滑）

查你们平台手册（周四任务）记录：各步态的最大线速/角速/加速度。

1.3.2 velocity smoother（速度斜坡，Nav2 内置）

为什么需要：规划器输出的速度可能"突跳"（从 0.5 突然到 1.5）。底盘执行突跳 = 狗急停/急冲。smoother 的作用 = 把速度变化"限速"：

输入 cmd_vel（可能突跳） → smoother → 输出斜坡化的 cmd_vel
规则：每 0.1s 速度变化 ≤ max_accel × 0.1

关键参数（velocity_smoother 插件）：

max_vel_x: 1.0          # 线速度上限
max_accel_x: 1.0        # 线加速度上限（爬坡）
max_decel_x: -1.0       # 减速度上限（刹得多急）
max_vel_theta: 1.0      # 角速度上限
max_accel_theta: 1.0    # 角加速度上限
feedback: true          # 用真实速度做反馈（更稳）

1.3.3 读源码（周四 20 分钟）

navigation2/nav2_velocity_smoother/：找参数处理 + 主循环（每个控制周期做"限速"），记录它"每周期对 cmd_vel 做了什么限制"。

一句话总结：四足约束 = 速度/加速度都要按步态限制；velocity smoother = 把速度突跳变成斜坡，防止狗急停急冲。

术语 大白话解释
