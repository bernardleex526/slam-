0.3 本周主线问题

两个传感器说的不一样，我信谁？ —— 信"更准的那个"，还要根据每次测量动态调整。Kalman 滤波就是这套"动态相信"的算法。

第 1 章 概率：怎么"相信"不确定的事

1.0 预备：样本空间、概率、随机变量（相当于 STAT110 L1–L2）

1.0.1 先打比方：掷骰子

  • 样本空间 = 所有可能的结果：{1, 2, 3, 4, 5, 6}。
  • 事件 = 你关心的结果集合：如"掷出偶数" = {2, 4, 6}。
  • 概率 = 事件发生的可能性（0~1 之间的数）：
  • P(掷出偶数) = 3/6 = 0.5。
  • P(永远不可能) = 0；P(一定发生) = 1。

概率的性质：所有结果的概率加起来 = 1；两个互斥事件至少一个发生 = 概率相加。

1.0.2 随机变量：把结果变成数字

  • 离散随机变量：结果是一个个数（骰子 1~6、传感器报文数）。
  • 连续随机变量：结果是一段范围内的任意值（速度 1.234…m/s、位置坐标）。

期望值（均值） = 长期平均：掷骰子 1000 次的平均值 ≈ 3.5。记作 E[X]。 方差 = 结果"散"不散（波动大不大）；标准差 = 方差的平方根（和原数据同单位）。

比喻：均值 = 平均值；方差 = "大家跟平均差多远"。

1.0.3 和机器狗的关系

机器狗的位置不是确定的数，而是"一个概率分布"——"我有 95% 把握在 3 米附近，误差 ±0.2 米"。SLAM 的输出就是这样：位置 + 不确定度（协方差）。本周学概率，就是为了看懂"不确定度"的语言。

一句话总结：概率 = 0~1 的可能性；样本空间 = 所有结果；随机变量 = 结果变数字；期望 = 平均值；方差 = 波动大小。

1.1 条件概率与贝叶斯公式（相当于 STAT110 L3，本周重点）

1.1.1 条件概率：有了新信息，重新评估

P(A | B) = "已知 B 发生了，A 发生的概率"（读作：在 B 条件下 A 的概率）。

例：机器狗在房间 A（60% 概率）或房间 B（40%）。突然激光测到"前方有楼梯"——房间 B 有楼梯的概率更大。看到楼梯后，重新评估"我在哪"——这就是条件概率。

公式：P(A|B) = P(A∩B) / P(B)

1.1.2 贝叶斯公式：新证据更新旧信念（核心！）

P(A|B) = P(B|A) × P(A) / P(B)

拆开看（SLAM 语言）：

P(位姿 | 观测) = P(观测 | 位姿) × P(位姿) / P(观测)
      ↑                ↑              ↑         ↑
  后验（信完新      似然（如果     先验（之前 归一化（保证加起来=1）
  证据后的把握）   位姿是真，      的把握）
                   看到这个观测
                   的可能性）

大白话：先验 × 似然 → 后验。"我原来这么想（先验）→ 看到新证据（似然）→ 更新想法（后验）"。这就是 SLAM/滤波器的灵魂：每一次测量都在更新信念。

1.1.3 例：机器狗版本

  • 先验：P(我在走廊) = 0.7。
  • 似然：如果在走廊，测到"两边都是墙"的概率 = 0.9。
  • 后验：P(我在走廊 | 测到两边墙) = 0.9 × 0.7 / P(观测) —— P(观测) 是"整体上测到两边墙的概率"，算出来最后结果约 0.95。

新证据让"在走廊"从 0.7 涨到 0.95。这就是贝叶斯更新。

一句话总结：贝叶斯 = 用新证据更新旧信念：后验 ∝ 似然 × 先验。滤波器（Kalman）就是反复做这件事。

1.2 连续分布与正态分布（相当于 STAT110 L7–L8）

1.2.1 连续分布

结果是一个范围内的任意值，用概率密度函数（pdf）描述：曲线高 = 那个值附近可能性大。曲线下方总面积 = 1。

1.2.2 正态分布（高斯分布）：宇宙最常用的分布

钟形曲线：中间高、两边低、对称
           μ（均值）    → 曲线的中心（最可能的值）
           σ（标准差）  → 曲线的胖瘦（σ 大 = 胖 = 不确定；σ 小 = 瘦 = 确定）

记号：X ~ N(μ, σ²)（读作：X 服从均值为 μ、方差为 σ² 的正态分布）。

为什么处处是高斯（中心极限定理，记住结论即可）：一堆独立小误差加起来，误差总和趋近正态分布。传感器的噪声基本都是高斯——这是 Kalman 滤波的前提。

68-95-99.7 法则：落在 μ±σ 内概率 68%，±2σ 内 95%，±3σ 内 99.7%。

1.2.3 和机器狗的关系

  • 噪声 = 高斯：激光测距误差 ≈ N(0, σ²)。这是数学模型的现实基础。
  • 状态 = 高斯：Kalman 滤波假设"我的位置信念是一个高斯分布"——均值 = 最可能的位姿，方差 = 不确定度。
  • 输出"位置 ± 不确定度"：其实就是"均值 ± 方差"的高斯。

一句话总结：正态分布 = 钟形曲线；μ 定中心、σ 定胖瘦；传感器噪声≈高斯；Kalman 就是"我的位置是个高斯，不断用测量把它变准"。

1.3 多元高斯：不止一个变量的高斯

1.3.1 从一维到多维

机器狗的状态有 6 个量（3 位置 + 3 姿态），每个量都有自己的不确定度，量之间还互相影响（x 不准，y 也可能受影响）。多元高斯 = 一堆变量的联合分布。

写法：均值向量 μ（每个变量的均值）+ 协方差矩阵 Σ（每对变量的关系）。

1.3.2 协方差矩阵：不确定度的"户口本"

Σ = | σx²   σxy |       对角线上 = 各自的方差（自己不确定多少）
    | σxy   σy² |       非对角线 = 协方差（两者一起变的趋势）
  • σxy > 0：x 偏大时 y 也偏大（正相关）。
  • σxy = 0：x、y 互不相干。
  • 几何上，Σ 对应一个椭圆（误差椭球）：主轴方向 = 特征向量，轴长 = 特征值开根号（第 1 周学过！）。

1.3.3 条件分布：只关注一部分变量

多元高斯条件分布 = 已知 x 的值，y 的条件分布是什么？结论（了解公式存在，会用工具即可）：

已知 x，y 的均值要修正（向"跟 x 相关的方向"靠），方差会缩小（信息更多，更确定）

这正是 Kalman 更新的数学：已知"激光观测"，修正"位置的均值"，缩小"方差"。

一句话总结：多元高斯 = 多变量的联合不确定度；协方差矩阵记录每个变量的方差和变量间的关系；条件分布 = 知道一部分变量后，其余变量的分布被修正（方差变小）。

1.4 一维 Kalman 滤波：手推全过程（本周核心）

1.4.1 场景

机器狗沿直线走。我们有两个信息：

  1. 预测：根据 IMU/运动模型，推测现在应该在 5m 处，但不确定（σ=0.5m）。
  2. 测量：激光测距仪说在 5.3m 处，也不确定（σ=0.2m）。

Kalman 滤波 = 把这两个信息按"谁更准信谁"合起来。

1.4.2 两步：预测（Predict）→ 更新（Update）

① 预测（Predict）：用运动模型向前推

x̂_预测 = x̂_上次 + 速度 × Δt
P_预测 = P_上次 + 过程噪声 Q        （走一步，不确定性变大一点）

② 更新（Update）：用测量修正

① 算"测量有多可信"：卡尔曼增益 K
   K = P_预测 / (P_预测 + R)         （R = 测量噪声方差）
   K 在 0~1 之间：K 大 = 信测量；K 小 = 信预测

② 修正均值：预测结果 + K × (测量 − 预测)
   x̂_更新 = x̂_预测 + K × (z − x̂_预测)
   （z − x̂_预测）叫"残差/新息"：测量和预测差多少

③ 修正方差：更新后不确定性变小
   P_更新 = (1 − K) × P_预测

1.4.3 数字例子（跟着算一遍）

  • 预测：x̂ = 5.0，P = 0.25（σ² = 0.5²）
  • 测量：z = 5.3，R = 0.04（σ² = 0.2²）
K = 0.25 / (0.25 + 0.04) = 0.25/0.29 ≈ 0.862   （测量更准，K 大 → 更信测量）
x̂_更新 = 5.0 + 0.862 × (5.3 − 5.0) = 5.0 + 0.259 ≈ 5.26
P_更新 = (1 − 0.862) × 0.25 ≈ 0.0345   （方差大幅缩小：更有把握了）

结果：位置从 5.0 修正到 5.26（偏向更准的测量），不确定性从 0.25 缩到 0.034。

下一次循环：把 x̂_更新、P_更新当"上一次"，再来一遍——预测 → 更新 → 预测 → 更新……这就是滤波器的循环。

一句话总结：Kalman = 预测（模型往前推，不确定性变大）+ 更新（用测量修正，按"谁准信谁"，不确定性变小），反复循环。

1.4 自测

  2. 数字例子：如果测量比预测更不准（R 很大），结果会怎样？
  3. 为什么更新后方差会变小？

第 2 章 ROS2：程序之间怎么"传话"

2.0 预备：ROS2 是什么

ROS2 = 机器人操作系统（不是真的操作系统，是一套"程序之间传数据"的框架 + 一堆现成工具）。

机器狗身上有很多程序：激光驱动、IMU 驱动、SLAM、导航、底盘控制……它们要互相传数据。ROS2 的答案是：

  话题（Topic）：广播——"我发数据，谁需要谁订阅"
  服务（Service）：问答——"你问我答"
  动作（Action）：长任务——"开始做、进度回报、可取消"
  参数（Parameter）：配置——"改设置"

2.2 写一个发布者 + 订阅者（C++）（覆盖"写两个 C++ 节点"任务）

发布者 publisher（发 /hello 消息）：

#include <rclcpp/rclcpp.hpp>
#include <std_msgs/msg/string.hpp>

int main(int argc, char** argv) {
    rclcpp::init(argc, argv);                          // 初始化
    auto node = std::make_shared<rclcpp::Node>("talker");  // 建节点
    auto pub = node->create_publisher<std_msgs::msg::String>("hello", 10);  // 建发布者
    rclcpp::Rate rate(1);                              // 每秒 1 次
    while (rclcpp::ok()) {
        auto msg = std_msgs::msg::String();
        msg.data = "你好，机器狗";
        pub->publish(msg);                             // 发布
        rate.sleep();
    }
    rclcpp::shutdown();
    return 0;
}

订阅者 subscriber（收 /hello 消息）：

#include <rclcpp/rclcpp.hpp>
#include <std_msgs/msg/string.hpp>

void callback(const std_msgs::msg::String::SharedPtr msg) {   // 收到消息自动执行
    RCLCPP_INFO(rclcpp::get_logger("listener"), "收到: %s", msg->data.c_str());
}

int main(int argc, char** argv) {
    rclcpp::init(argc, argv);
    auto node = std::make_shared<rclcpp::Node>("listener");
    auto sub = node->create_subscription<std_msgs::msg::String>(
        "hello", 10, callback);                          // 订阅 + 绑定回调
    rclcpp::spin(node);                                  // 挂起，等消息
    return 0;
}

回调（callback）：你上周看 FAST-LIO2 时见过"laserCloudHandler"——它就是回调：数据一到，程序自动执行这个函数。这是 ROS 编程的骨架。

2.5 TF2：坐标系关系广播站（本周核心概念）

2.5.1 TF 是什么

机器狗有多个坐标系（世界系、机体系、雷达系、IMU 系……）。每个程序都需要知道"坐标系之间什么关系"——TF 就是"谁在谁的哪里"的广播表。

TF 树（坐标系关系树）：
map（地图系）
 └── odom（里程计系）
      └── base_link（机体系）★
           ├── laser（雷达系）
           ├── imu_link（IMU 系）
           └── 四条腿的关节系…

TF 树 = 坐标系的家谱。任何两个坐标系之间，沿着树找路径就能算变换（比如"雷达看到的点，在世界系坐标是多少"）。

2.5.2 两种 TF（记住区别）

  • 静态变换：永远不变的（雷达装在机体的位置）——发布一次就行。
  • 动态变换：不断变化的（机体在世界里的位姿）——实时更新。

3.1 IMU 数据怎么进系统

回头看第 1 周数据流图第 ① 步。IMU 在 FAST-LIO2 里的路径：

IMU 硬件 → 驱动 → /livox/imu 话题（200Hz）

   → 主回调：取出一段 IMU → esekf.predict() 状态传播

关键字段（看 sensor_msgs/msg/Imu 消息）：

字段 含义
linear_acceleration 加速度（x,y,z）
angular_velocity 角速度（x,y,z）
orientation 四元数姿态（可选，不常信）

4.1 任务 1：一维 Kalman 实现 + 三个场景测试（90 分钟，核心交付）

用 Python 实现一维 Kalman（或 C++，你选）：

import numpy as np
import matplotlib.pyplot as plt

def kalman_predict(x, P, Q, v, dt):
    """预测：匀速模型 x' = x + v*dt"""
    x_pred = x + v * dt
    P_pred = P + Q               # 过程噪声：不确定性变大
    return x_pred, P_pred

def kalman_update(x_pred, P_pred, z, R):
    """更新：用测量 z 修正"""
    K = P_pred / (P_pred + R)    # 卡尔曼增益
    x_upd = x_pred + K * (z - x_pred)
    P_upd = (1 - K) * P_pred
    return x_upd, P_upd, K

# 仿真：真值 = 匀速直线 + 噪声测量
np.random.seed(42)
true_x = 0.0
v = 0.5                          # 速度 0.5 m/s
dt = 0.1
R = 0.04                         # 测量噪声方差（σ=0.2）
Q = 0.01                         # 过程噪声
N = 100

x, P = 0.0, 1.0                  # 初始状态（很没把握）
traj, meas, est = [], [], []
for i in range(N):
    true_x += v * dt
    z = true_x + np.random.normal(0, np.sqrt(R))   # 测量 = 真值 + 噪声
    x, P = kalman_predict(x, P, Q, v, dt)
    x, P, K = kalman_update(x, P, z, R)
    traj.append(true_x); meas.append(z); est.append(x)

plt.plot(traj, 'k-', label='真值'); plt.plot(meas, 'r.', label='测量（噪声）')
plt.plot(est, 'b-', label='Kalman 估计')
plt.legend(); plt.grid(); plt.savefig('kalman1d.png', dpi=150)

✅ 检查点：蓝线明显比红点平滑、贴近黑线。

三个场景测试（记录结果）： 1. 噪声大（R=4）：估计线会"不太跟测量"——K 小，更信预测。 2. 噪声小（R=0.0004）：估计线紧贴测量——K 大，信测量。 3. 模型失配（真值突然加速，模型还是匀速）：估计会滞后——这解释了"模型错 + 信模型 = 误差"。

输出：三张对比图 + 每张图一句话结论，存仓库提交 git。
