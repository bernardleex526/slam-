0.3 本周主线问题

机器狗颠一下，激光点云会错多少？ —— 数学上就是"颠簸量（输入）→ 点的位置偏差（输出）"的关系，这个关系就是雅可比。本周学完全部能回答。

第 1 章 微积分：研究"变化"的数学

1.0 预备：什么是导数（相当于 3B1B 微积分 V1–V2）

1.0.1 先打比方：车速表

你开车，速度表显示"80 公里/小时"——这是某一瞬间的速度。怎么来的？给你一张"位置—时间"图（横轴时间，纵轴位置）：

  • 两点之间求平均速度 = 路程 ÷ 时间 = 这条线的斜率（陡不陡）。
  • 导数 = 某一瞬间的斜率 = 让两点的间隔无限缩小后的平均速度。

导数就是"变化的速度"。位置对时间的导数 = 速度；速度对时间的导数 = 加速度。

1.0.2 怎么算：公式

导数 = 求斜率。常用规则（背下来，后面手推雅可比要用）：

函数 导数
常数 c 0
x（一次方） 1
x² 2x
x³ 3x²
xⁿ n·xⁿ⁻¹
sin(x) cos(x)
cos(x) −sin(x)
eˣ eˣ
ln(x) 1/x

写法：f(x) 的导数写作 f′(x) 或 df/dx（读作 d f d x，"x 一变，f 变多少"）。

例：f(x) = x²，则 f′(x) = 2x。在 x=3 处，斜率 = 6（曲线在 3 处很陡）。

1.0.3 和机器狗的关系

  • 位置对时间求导 = 速度（机器狗运动学的基础）。
  • 旋转对时间求导 = 角速度——IMU 测的就是它。
  • 后面"机体起伏 → 点云畸变"的推导，就是"位姿变一点，点的位置变多少"——这是个导数问题。

一句话总结：导数 = 某一瞬间的变化速度 = 斜率；位置→速度→加速度就是一层层求导。

1.1 链式法则：函数的套娃（相当于 3B1B 微积分 V3）

1.1.1 先打比方：工厂流水线

工厂有两道工序：先把原料放大 2 倍（工序 A），再求平方（工序 B）。原料变一点，最终产品变多少？——两道工序的变化率相乘。

1.1.2 公式

如果 y = f(g(x))（先算 g，再算 f），则：

dy/dx = f′(g(x)) × g′(x)

"外层导数 × 内层导数"。

例：y = (2x+1)²。外层是"平方"（导数 2·(2x+1)），内层是 2x+1（导数 2），所以：

dy/dx = 2(2x+1) × 2 = 4(2x+1) = 8x + 4

1.1.3 和机器狗的关系

坐标变换链就是套娃：点世界坐标 = T_世界机体 × (T_机体雷达 × 点雷达坐标)。位姿变一点，点的世界坐标变多少 = 每层变换的导数相乘——这就是雅可比要用链式法则的原因（本周三）。

一句话总结：链式法则 = 套娃函数的导数 = 外层导数 × 内层导数；坐标变换链求导全靠它。

1.2 极值：找最大最小（相当于 3B1B 微积分 V4）

1.2.1 先打比方：爬山

爬到山顶时，脚下是平的——斜率 = 0。所以"找极值（最大/最小）"的办法：求导数，令导数 = 0，解方程。

  • 导数 = 0 的地方叫驻点，可能是最大、最小或"鞍点"（马鞍中间）。
  • 判断是哪种：看二阶导数 f″(x)——正的 = 凹向上 = 极小值；负的 = 凹向下 = 极大值。

1.2.2 和机器狗的关系

优化（找最好）是 SLAM 的核心：调整位姿让"所有点到面的距离之和"最小——这就是最小二乘。找最小值的方法 = 求导置零（第 4 周 Gauss-Newton 就是迭代做这件事）。

一句话总结：极值 = 导数 = 0 的地方；找"最好位姿" = 让误差函数的导数 = 0。

1.3 积分：把变化累加起来（相当于 3B1B 微积分 V5–V8，了解即可）

1.3.1 先打比方：算路程

速度表不是固定的——一会儿快一会儿慢。算总路程 = 把每个瞬间的速度 × 那一小段时间，全部加起来。这就是积分（微分的逆运算：导数是"拆"，积分是"拼"）。

  • 几何上：积分 = 曲线下方的面积。
  • 例子：匀速 60 km/h 跑 2 小时，路程 = 60 × 2 = 120 km = 面积。

1.3.2 和机器狗的关系

IMU 积分 = 猜位置：IMU 每 0.005 秒给一个加速度，把"加速度 × 时间"逐段累加 = 速度；再把"速度 × 时间"累加 = 位移。这就是第 1 周数据流图里"IMU 状态传播"的数学本质——不断累加（积分），所以误差会累积（这就是 IMU 会漂的原因）。

一句话总结：积分 = 把微小的变化累加起来（面积的直觉）；IMU 猜位置就是不断积分，所以会漂。

1.4 梯度、雅可比、海森矩阵：多变量的导数（覆盖 MML 第 5 章）

1.4.1 从"一个变量"到"一堆变量"

前面学的导数都是"一个输入 → 一个输出"。但机器狗的状态有几十个量（位置 3 个、姿态 3 个、速度 3 个、零偏 6 个……），输出也有几十个。需要一个"一览表"记录：每个输入变一点，每个输出变多少——这个表就叫雅可比矩阵。

1.4.2 三种"多变量导数"（背概念，不用背公式）

名字 是什么 例子
梯度 一个函数对一堆变量的导数，排成向量 f(x,y) 的梯度 = (∂f/∂x, ∂f/∂y)，指向"上升最快"的方向
雅可比矩阵 J 一堆函数对一堆变量的导数，排成矩阵 3 个输出、2 个输入 → 3×2 矩阵，每个格子 = 一个输出对一个输入的偏导
海森矩阵 H 二阶导数，排成矩阵 衡量"弯曲程度"，优化算法用来判断怎么走最稳

写法：对 x 求偏导写 ∂f/∂x（念"partial"——把其他变量当常数，只对 x 求导）。

1.4.3 雅可比到底怎么用（重点）

设机器狗位姿是 p（输入），一个激光点的世界坐标是 y（输出）。雅可比 J = "p 变一点点，y 变多少"的表格。 

Δy ≈ J × Δp
  • 知道 J，就知道"位姿错多少 → 点会偏多少"——反过来也能从"点偏了多少"推"位姿该改多少"。
  • 第 4 周 Gauss-Newton 的核心就是算 J。FAST-LIO2 的配准也是这么干的。

一句话总结：梯度 = 一函数对多变量的变化方向；雅可比 = 多输出对多输入的变化表；海森 = 二阶变化表。位姿和点偏差的关系就是雅可比。

1.5 手推：2D 旋转的雅可比（本周第一个核心技能）

1.5.1 场景

点 (x, y) 绕原点逆时针转 θ 度（第 1 周 1.5 节学过）：

x′ = x·cosθ − y·sinθ
y′ = x·sinθ + y·cosθ

问题：θ 变一点点（比如转错 0.001 弧度），点的坐标变多少？ 这就是"旋转角对点坐标的雅可比"。

1.5.2 手推（照抄一遍，自己写一遍）

对 θ 求偏导（把 x、y 当常数）：

∂x′/∂θ = x·(−sinθ) − y·cosθ     （cosθ 的导数是 −sinθ；sinθ 的导数是 cosθ）
∂y′/∂θ = x·cosθ − y·(−sinθ)   →   x·cosθ + y·sinθ

写成矩阵（2 个输出对 1 个输入）：

J = | ∂x′/∂θ |   =   | −x·sinθ − y·cosθ |
    | ∂y′/∂θ |       |  x·cosθ + y·sinθ |

验证直觉：θ=0 时（还没转），点 (1, 0)：J = (−0−0, 1·1+0) = (0, 1)。意思是：θ 增一点点，点往上挪一点——对！刚开始转时，右方的点往上走。

1.5.3 手推：极坐标→直角坐标的雅可比

极坐标 (r, θ) 转直角坐标 (x, y)：

x = r·cosθ
y = r·sinθ

对 r 和对 θ 分别求偏导：

∂x/∂r = cosθ      ∂x/∂θ = −r·sinθ
∂y/∂r = sinθ      ∂y/∂θ =  r·cosθ

J = | cosθ   −r·sinθ |
    | sinθ    r·cosθ |

一句话总结：雅可比手推 = 把每个输出对每个输入求偏导，排成表。旋转雅可比 = 用 sin/cos 求导规则对旋转公式求导。

1.6 四元数：绕任意轴旋转的工具（相当于 3B1B 四元数视频）

1.6.1 先打比方：为什么不用欧拉角？

用"翻身/点头/扭头"（roll/pitch/yaw）描述姿态有个著名问题：万向锁（当 pitch 转到 ±90° 时，roll 和 yaw 会互相"抢戏"，姿态没法唯一表示），而且插值不平滑。

四元数 = 一个更聪明的姿态表示法：一个四元数 q = (w, x, y, z) 就像"绕一根轴转一个角度"的打包：

q = (cos(θ/2),  sin(θ/2)·轴x,  sin(θ/2)·轴y,  sin(θ/2)·轴z)
  • 绕 z 轴转 θ = 轴 (0,0,1)：q = (cos(θ/2), 0, 0, sin(θ/2))。
  • 单位四元数（长度 1）表示姿态；负号代表同一个旋转（q 和 −q 一样）。

1.6.2 三兄弟互转（周六实验用 Eigen 验证）

旋转矩阵 R（3×3） ⟷ 四元数 q（4 个数） ⟷ 欧拉角（roll/pitch/yaw）。转换公式复杂，但 Eigen 一行搞定：

Eigen::Quaterniond q(rot_matrix);          // 矩阵 → 四元数
Eigen::Matrix3d R = q.toRotationMatrix();  // 四元数 → 矩阵
Eigen::Vector3d euler = R.eulerAngles(0, 1, 2);  // 矩阵 → 欧拉角（x-y-z 顺序）

1.6.3 为什么 SLAM 用四元数

  • 无万向锁、插值平滑。
  • 快速组合旋转：q1 × q2 = 先 q2 后 q1（和矩阵一样从右往左读）。
  • 存 4 个数比 9 个数的矩阵省空间——你上周看到的 States.rot 是 12 维，那是因为 FAST-LIO2 用"旋转矩阵列向量化 + 冗余维"的存法，下周（第 3 周讲完）再看就会更明白。

一句话总结：四元数 = "绕一根轴转一个角度"的姿态包；能避免万向锁；和旋转矩阵/欧拉角可以互相转换。

2.0 类：把数据和函数打包（覆盖第 7 章）

2.0.1 先打比方：点结构升级版

第 1 周你认识了 PointXYZINormal（一个点的数据结构）。类（class）就是"数据 + 操作这些数据的函数"打包在一起——像一个带使用说明的盒子。

class Point {
public:                      // public：外面可以访问
    double x, y, z;          // 数据（成员变量）

    void print() {           // 函数（成员函数/方法）
        std::cout << "(" << x << ", " << y << ", " << z << ")" << std::endl;
    }
};

Point p;                     // 创建对象（"实例化"）
p.x = 1.0; p.y = 2.0; p.z = 3.0;
p.print();                   // 调用方法：输出 (1, 2, 3)
  • public：公开的，外面能用。
  • private：私有的，只有类自己的函数能用（保护数据不被乱改）。
  • 构造函数：创建对象时自动执行的函数（用来初始化）：
class Point {
public:
    double x, y, z;
    Point(double a, double b, double c) : x(a), y(b), z(c) {}   // 构造函数
};
Point p(1.0, 2.0, 3.0);      // 创建时直接给值

2.0.2 和机器狗的关系

  • FAST-LIO2 里的 States、PointXYZINormal 都是"结构体"，C++ 里 struct 和 class 几乎一样（struct 默认 public）。
  • ROS 节点、layer（costmap 的层）都是类——"类 = 一个模块"。看到 .cpp 文件里的类，就理解成"一个打包好的功能模块"。

一句话总结：类 = 数据 + 方法打包；public 对外、private 对内；构造函数 = 创建时初始化。

第 3 章 costmap：机器人的"危险地图"

3.1 costmap 是什么（先打比方）

导航时机器人要知道"哪里能走、哪里不能走"。costmap（代价地图）= 一张网格图，每个格子一个数（0~254）：数越大越危险。

0   0   0   0   0   0
0   0   0  254 254 0      ← 254 = 障碍物（墙）
0   0  50  254 254 0      ← 50  = 靠近墙，危险但可以慢点走
0   0   0   0   0   0
  • 0：放心走。
  • 254：障碍物，不能走。
  • 中间值：靠障碍越近越危险（"膨胀"出来的安全区）。

nav2_costmap_2d 就是生成这张图的程序，它由几个"层（layer）"叠加而成。

3.2 costmap 的层次结构（本周核心知识）

        最终代价地图
        ┌────────────────────┐
        │  Static Layer      │ 静态层：来自预先建好的地图（SLAM 建图的结果）
        ├────────────────────┤
        │  Obstacle Layer    │ 障碍层：激光雷达实时测到的障碍（动态的！）
        ├────────────────────┤
        │  Inflation Layer   │ 膨胀层：给障碍物"画个安全圈"（危险渐变）
        ├────────────────────┤
        │  Voxel Layer(可选) │ 体素层：3D 版本（可处理立体障碍）
        └────────────────────┘

三层是叠起来的（每个格子取各层最大/相加）。你周一~周三分别读一层。

costmap_2d_ros.cpp 入口做了啥（大白话）： 1. 创建代价地图对象（分配格子数组）。 2. 从参数文件读配置（宽度、高度、分辨率）。 3. 创建所有配置的 layer 对象，把它们"叠"在一起。 4. 订阅传感器话题（激光、点云）→ 数据来了让障碍层更新格子。

3.4 inflation_layer：给障碍"画安全圈"（覆盖 inflation 任务）

膨胀层做什么：把障碍物格子周围一圈的格子，按"距离"赋一个危险值（越近越大）。这样机器人不会贴墙走。

核心概念：膨胀半径 inflation_radius（危险区有多远）和cost scaling factor（衰减多快）。

主流程（代码里你会看到的样子）：

1. 拿到障碍物格子的坐标列表
2. 对每个障碍格子：
   对周围半径内的每个格子：
     算距离 d（到障碍物多远）
     代价 = 255 × (1 − d / 膨胀半径) 的某种衰减
3. 把算出的代价写进地图

inflation_layer.cpp 里的核心函数：computeCost()（算一个格子的代价）和主循环 updateCosts()。

3.5 obstacle_layer：实时障碍怎么进来（覆盖 obstacle 任务）

障碍层做什么：激光雷达每帧点云 → 判断哪些点是障碍物 → 写进对应格子 → 变成 254。

主流程：

1. 收到点云（或激光扫描）
2. 每个点转成网格坐标（世界坐标 → 行列号）
3. 打射线：从机器人位置到每个点画一条线
   → 线经过的格子 = "空"（能看到 = 没障碍）
   → 点所在的格子 = "占用"（有障碍）
4. 更新格子（标记）

这就是"传感器 → 障碍层 → 膨胀层 → 代价图"的流程——周六你要画出这张图。

4.1 任务 1：2D 旋转雅可比 vs 有限差分（60 分钟，本周核心实验）

有限差分 = 不用求导公式，直接用"小变化"近似导数：

导数 ≈ [f(x + h) − f(x)] / h       （h 是一个很小的数，如 1e-6）

你的任务：用两种方法算旋转雅可比，对比误差 < 1e-6。

#include <Eigen/Dense>
#include <iostream>

// 方法1：解析（公式推导的结果，1.5 节手推过）
Eigen::Vector2d jacobian_analytic(double x, double y, double theta) {
    Eigen::Vector2d J;
    J << -x * sin(theta) - y * cos(theta),
          x * cos(theta) + y * sin(theta);
    return J;
}

// 方法2：有限差分（用定义硬算）
Eigen::Vector2d jacobian_fd(double x, double y, double theta, double h = 1e-6) {
    // 旋转公式
    auto rot = [&](double t) -> Eigen::Vector2d {
        return Eigen::Vector2d(x * cos(t) - y * sin(t),
                               x * sin(t) + y * cos(t));
    };
    Eigen::Vector2d fp = rot(theta + h);   // 转多一点点
    Eigen::Vector2d fm = rot(theta - h);   // 转少一点点
    return (fp - fm) / (2 * h);            // 中心差分：更准
}

int main() {
    double x = 2.0, y = 1.0, theta = 0.3;
    std::cout << "解析: "   << jacobian_analytic(x, y, theta).transpose() << "\n";
    std::cout << "有限差分: " << jacobian_fd(x, y, theta).transpose() << "\n";
    std::cout << "误差: " << (jacobian_analytic(x, y, theta) - jacobian_fd(x, y, theta)).norm() << "\n";
    return 0;
}

✅ 检查点：误差 < 1e-6（h 取 1e-6 时中心差分精度约 h² = 1e-12 量级）。 思考：为什么中心差分比单侧差分 (f(x+h)−f(x))/h 更准？→ 因为对称抵消了误差。

再验证一个场景：θ = 90°（0.5π）时再比一次，误差仍然 < 1e-6 吗？

提交 git。

4.2 任务 2：四元数 ↔ 旋转矩阵 ↔ 欧拉角互转验证（40 分钟）

#include <Eigen/Geometry>
#include <Eigen/Dense>
#include <iostream>

int main() {
    // 绕 z 轴转 30°，绕 x 轴转 20°，组合
    Eigen::AngleAxisd rz(30.0 * M_PI / 180.0, Eigen::Vector3d::UnitZ());
    Eigen::AngleAxisd rx(20.0 * M_PI / 180.0, Eigen::Vector3d::UnitX());
    Eigen::Matrix3d R = (rz * rx).toRotationMatrix();   // 旋转矩阵

    Eigen::Quaterniond q(R);              // 矩阵 → 四元数
    Eigen::Matrix3d R2 = q.toRotationMatrix();         // 四元数 → 矩阵
    std::cout << "矩阵往返误差: " << (R - R2).norm() << "\n";   // 应 < 1e-15

    // 用四元数旋转一个点
    Eigen::Vector3d v(1, 0, 0);
    Eigen::Vector3d r1 = q * v;                     // 四元数旋转
    Eigen::Vector3d r2 = R * v;                     // 矩阵旋转（一样）
    std::cout << "旋转结果差: " << (r1 - r2).norm() << "\n";    // 应 < 1e-15
    return 0;
}

✅ 检查点：两个误差都 < 1e-15。
