第 1 章 EKF：多变量、非线性的 Kalman

1.0 从 Kalman 到 EKF（覆盖《概率机器人》第 2 章思路）

1.0.1 回顾一维 Kalman（第 3 周）

预测：x' = x + v·Δt          （用模型往前推）
更新：x ← x + K·(z − x')      （用测量修正，K = 信测量程度）

1.0.2 两个问题

  1. 多变量：状态是"位置 3 个 + 姿态 3 个 + 速度 3 个 + 零偏 6 个"，不是一个数 → 所有量都变成向量，方差变成协方差矩阵（第 3 周学过）。
  2. 非线性：运动模型和测量模型大多不是直线关系（旋转是 sin/cos！）→ 直接套 Kalman 公式失效。

1.0.3 EKF 的答案（一句话）

EKF = 在每个当前状态处，把非线性函数"拉直"（用雅可比线性化，第 2 周学的），然后套 Kalman 公式。

f(x) ≈ f(x₀) + J·(x − x₀)      ← 一阶泰勒展开（第 4 周也用过）

代价：线性化有误差 → EKF 在"非线性强"的地方会不准 → 这就是为什么 FAST-LIO2 用迭代（iEKF，反复线性化）。

1.0.4 和机器狗的关系

  • 机器狗状态：位置、姿态（四元数/旋转矩阵）、速度、IMU 零偏。
  • 传感器：里程计（测位移）、IMU（测角速度+加速度）、激光定位（测绝对位置）。
  • EKF 把多个传感器的信息按"各自有多准"融合成一个最优估计 —— 这就是 robot_localization 包干的事（本周实验用）。

一句话总结：EKF = 多变量 + 非线性的 Kalman：用雅可比把非线性拉直，再套 Kalman 公式。

1.1 手推 EKF 预测/更新（本周核心，写满一页纸）

1.1.1 记号

状态向量：x（如 15 维：位置 3 + 姿态 3 + 速度 3 + 零偏 6）
协方差矩阵：P（不确定度）
运动模型：x' = f(x) + 噪声       （非线性，用雅可比 F 线性化）
测量模型：z = h(x) + 噪声        （非线性，用雅可比 H 线性化）
过程噪声 Q、测量噪声 R（第 3 周学过）

1.1.2 预测步（Predict）

① x̂⁻ = f(x̂)                    （用模型往前推状态）
② P⁻ = F·P·Fᵀ + Q              （不确定性变大：F = 运动模型雅可比，Q = 过程噪声）

对照一维版：x' = x + vΔt（变成了 f），P' = P + Q（变成了 FPFᵀ + Q——矩阵版"不确定变大"）。

1.1.3 更新步（Update）

① 残差（新息）：y = z − h(x̂⁻)          （测量 − 预测的测量）
② 创新协方差：S = H·P⁻·Hᵀ + R
③ 卡尔曼增益：K = P⁻·Hᵀ·S⁻¹           （矩阵版 K）
④ 修正状态：x̂ = x̂⁻ + K·y
⑤ 修正协方差：P = (I − K·H)·P⁻

对照一维版：K = P/(P+R) → 变成了矩阵式；x̂ = x̂⁻ + K·y 完全一样；P 缩小 → P 也缩小。

1.1.4 手推任务（周五前完成）

写满一页纸，三栏：

| 一维 Kalman（第 3 周） | EKF 矩阵版 | 一句话解释 |
| K = P/(P+R)            | K = P⁻Hᵀ(HP⁻Hᵀ+R)⁻¹ | 信测量的程度 |
| x' = x + vΔt           | x̂⁻ = f(x̂)          | 模型预测 |
| ...                    | ...                 | ... |

写完全部对照，你就真的懂了 EKF。

一句话总结：EKF = 把一维 Kalman 的每个公式换成矩阵版，并在预测/测量处用雅可比线性化。

1.2 四足里程计特性（覆盖资料任务，周三）

1.2.1 里程计是什么

里程计 = "我走了多远"的估计。轮式车：轮子转了几圈 × 轮周长 = 位移（比较准）。四足狗：没有轮子，靠的是"腿的关节角度 + 机身 IMU"反推身体移动 = 腿部里程计。

1.2.2 四足里程计漂移的 5+ 个来源（本周核心清单，逐条理解）

# 来源 大白话 影响
1 打滑 脚和地面打滑，腿动了但身体没动那么多 里程计说走了 2m，实际 1.8m
2 机身浮动 走路时身体上下颠、左右晃（浮动基座） 里程计混入"晃动"当"前进"
3 航向漂移 转弯时角度的微小误差不断累积 走直线变成走弧线
4 支撑相/摆动相 脚抬起来时关节角度在变但没位移 需要区分"哪只脚在着地"
5 地面材质 草地/沙地 vs 水泥地，打滑程度不同 同样的腿运动，位移不同
6 坡度 上坡/下坡，水平位移 ≠ 腿轨迹 垂直方向误差影响水平

→ 结论：浮动基座是主要漂移源还是次要？

这就是"把观察变成数据"的训练——你以后分析漂移问题都要这么干。

一句话总结：四足里程计漂移主要来自：打滑、机身浮动、航向漂移、支撑相判断、地面材质、坡度。知道"哪在漂"才能知道"怎么修"。

1.3 UKF、误差状态滤波、李群李代数（了解层，周四）

1.3.1 UKF：不用线性化的 Kalman

UKF 不把非线性函数拉直，而是采样一堆点（sigma 点），把这些点过一遍非线性函数，再统计出新分布。对强非线性更准，但计算量大。 了解即可。

1.3.2 误差状态滤波（ESKF）：FAST-LIO2 的家族

思想：把状态拆成"名义状态 + 误差状态"：

真实状态 ≈ 名义状态（大数，用 IMU 积分）⊕ 误差状态（小数，用滤波估计）

为什么：旋转在高斯假设下"不能直接加"（转 30° + 转 30° ≠ 转 60°？是，但协方差传播很麻烦）。误差状态是微小量，微小旋转可以当向量直接加——数学就简单了，精度还高。FAST-LIO2 的 ESKF 就是这个套路。

1.3.3 李群李代数：旋转的"正确数学"（《视觉SLAM十四讲》第 4 章）

为什么旋转不能当普通向量：

  • 旋转矩阵乘积（组合旋转）不是"加法"；旋转矩阵对时间的导数公式复杂。
  • 李群 SO(3) = 所有旋转矩阵的集合；李代数 so(3) = 旋转矩阵"附近"的微小旋转（3 维向量）。
  • 指数映射 exp：so(3) → SO(3)：微小旋转 → 旋转矩阵（"微小量累加"的正确方式）。
  • 对数映射 log：SO(3) → so(3)：旋转矩阵 → 微小旋转。

一句话："旋转"有自己的加减法规则——用李代数做微分/扰动，用指数映射回到旋转矩阵。 FAST-LIO2 在流形上迭代更新 = 每次修正都用 so(3) 算、再 exp 回 SO(3)。

本周要求：能说出"为什么不能直接加旋转矩阵"和"exp/log 是干嘛的"即可，公式不要求手推。

一句话总结：ESKF = 估计微小误差状态；李代数 = 旋转的"微分空间"，exp/log 在微小旋转和旋转矩阵之间来回。

1.4 IMU 标定与 Allan 方差（覆盖资料任务，周五）

1.4.1 IMU 的噪声模型

IMU 输出有两个系统误差要估计：

误差 含义 表现
零偏（bias） 静止时也不归零的偏移 静止时角速度显示 0.01 rad/s
噪声（噪声密度） 随机抖动 读数来回跳

还有比例因子、安装误差（出厂标定处理）。零偏会随温度/时间缓慢变化——所以 SLAM 把它放进状态里持续估计（你见过 b_gyr、b_acc！）。

1.4.2 Allan 方差：看噪声"长相"的工具

Allan 方差 = 把 IMU 静止数据切成长短不同的段，看"平均后还抖多少"：

切得越长 → 抖动怎么变？
- 随机噪声：变短（平均掉了）
- 零偏游走：变长（零偏在漂）
- 曲线折点：区分噪声类型

产出：角度随机游走、零偏不稳定性等参数 → 填进滤波器的 Q/R。

1.4.3 为什么要知道这些

  • 滤波器 Q、R 设多大，取决于 IMU 噪声水平。
  • 看到"定位漂移"先怀疑：IMU 零偏没估好？（对比静止时 odom 姿态是不是在飘）

一句话总结：IMU 误差 = 零偏（慢慢漂）+ 随机噪声；Allan 方差用来测它们；零偏要放进滤波器状态里实时估计。

2.0 robot_localization 入门（周一）

robot_localization = 开源多传感器融合包（EKF/UKF 两种）。用它的步骤：

# ekf.yaml（最小配置）
ekf_filter_node:
  ros__parameters:
    frequency: 30.0                 # 滤波频率
    odom0: /odom_raw                # 输入 1：里程计
    odom0_config: [true, true, false,   # x, y, z（不使能 z）
                   false, false, false, # roll, pitch, yaw
                   true, true, false,   # vx, vy, vz
                   false, false, false,
                   false, false, false]
    imu0: /imu/data                 # 输入 2：IMU
    imu0_config: [false, false, false,
                  true, true, true,     # 使能 roll pitch yaw（姿态）
                  ...]
    odom0_differential: false
    two_d_mode: true                # 平面运动模式（多数导航用）

配置的本质：告诉滤波器"每个传感器提供哪些维度的信息"（true = 用这个维度）。
